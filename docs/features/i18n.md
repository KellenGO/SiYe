# 界面语言（中英双语与文档语言）

## 一句话

界面可在中文与英文之间切换。切换后连 `<html lang>` 和标签页标题一起改，
屏幕阅读器不会再用中文发音规则念英文界面。

## 代码入口

| 职责 | 位置 |
|---|---|
| i18n 初始化、语言切换副作用（`lang` / 标题） | `webui/src/i18n/index.ts` |
| 中文文案 | `webui/src/i18n/locales/zh-CN/common.json` |
| 英文文案 | `webui/src/i18n/locales/en-US/common.json` |
| 许可弹窗文案 | `webui/src/i18n/locales/zh-CN/license.json` |
| 语言选择控件 | `webui/src/components/layout/LanguageSwitch.tsx` |

## 关键决定

- 语言存在 `localStorage['mediacrawler_language']`，检测顺序 `localStorage` → `navigator`，
  `fallbackLng` 是 `zh-CN`。
- `webui/index.html` 里的 `lang="zh-CN"` 只是首屏默认值。运行时由 `languageChanged` 事件
  覆盖成当前语言，标签页标题按 `brand.name · brand.subtitle` 重算——否则英文界面下
  屏幕阅读器仍按中文念，浏览器「是否翻译此页」也可能误判。
- 英文界面里品牌名用 `SiYe`（项目命名约定：中文场景写四野，需要 ASCII 时写 SiYe）。
- 平台名（小红书 / 抖音 / B站 / 知乎）按专有名词保留原样，不翻译。

## 已知坑 / 边界

- **覆盖不完整**：首页、顶栏、页脚、设置页、扩展页已走 i18n；收藏页
  （`webui/src/components/favorites/FavoritesPage.tsx`）和帮助页正文仍是大量硬编码中文，
  英文界面下会中英混杂。整页国际化需要单独一批文案，不要顺手改一半。
- 新增 `t("ns.key")` 时两个 locale 必须一起加。`tests/test_webui_ui_contract.py` 守两件事：
  源码里用到的键必须在每个 locale 存在；两个 locale 的键集合必须一致。
- **`common.json` 是混合行尾**（大部分 CRLF，个别行 LF）。不要 `json.loads` + `json.dumps`
  整份写回——那会把 LF 行也变成 CRLF，diff 里凭空多出一堆无关行。只替换目标区块的原文，
  用 `newline=""` 读写。
- 改源码里被正则解析的结构（如教程的 `GUIDE_STEPS`）之后，要复核守卫是否还在管它：
  2026-09-23 给步骤加字段后，原正则整条失配，守卫照样绿但已经不管了。
- `FavoritesPage` 这类页面里的 `aria-label` 也还是中文。给新加的无障碍名称走 i18n 时，
  注意同页其他 `aria-label` 还没走，别以为已经统一了。

## 测试怎么跑

  首页与搜索页除平台名外没有中文文本节点。
