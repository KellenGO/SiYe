# 新手引导

## 一句话

首次进入时提供可跳过的邀请，用户主动开始后，跟着真实页面走七步（账号 → 首页 → 搜索 → 收藏 → 观看历史 → 外观 → 帮助），一步一页；需要指认某个控件的步骤，页面会压暗并把目标框出来（跟着滚动走、不拦点击）；每个页面的完整说明常驻帮助页的「页面与功能一览」。

## 关键决定

- **一步一页**：`GUIDE_STEPS` 是唯一来源 —— `key` 决定文案键（`onboarding.<key>Title` / `<key>Body` / `<key>Action`），`route` 决定这一步落到哪个页面。加删步骤只改这一处加两份 locale；`initialGuideState` 的步数校验按长度动态判断，不再写死具体数字。
- 先邀请、用户主动开始；提示卡占正常页面空间，不覆盖按钮、不限制页面操作。每一步可以导航到实际页面，用户准备好后手动继续，允许直接跳到任意步骤。
- **长文案不塞进卡片**：卡片只讲「这一页是什么 + 你能做什么」，逐页细目放在帮助页「页面与功能一览」；卡片页脚（`onboarding.replayHint`）负责指路，两边的互相指认由 `tests/test_webui_ui_contract.py` 的守卫绑住。
- 收藏步骤用两句用户文案区分日常同步只新增与重置同步覆盖本机跨平台收藏，并说明两者都不改平台收藏；操作细节留在使用说明的「高级功能说明」。
- **平台勾选框的文案与真实行为必须一致**：教程写「默认一个都不勾，由你亲手勾」，因此偏好的语义是
  **"用户最后一次勾的样子，含一个都不勾"**：存储没有这个键时返回空集，显式空数组也返回空集
  （`parsePlatformPref`）—— 此前写回存储的 `[]` 会被当成"解析不出平台"而回退全选，页面往返一次就变成四个平台全勾；
  取消到零也一样要落地，否则用户取消过的平台会在刷新后自己勾回来。详见
  `docs/decisions/2026-09-23-平台偏好空数组语义.md`。
- 只建议先连接常用的 1–2 个平台；向导不替用户勾平台，不代替用户登录、搜索或同步收藏。
- 「搜索与查看」那一步说明平台按钮**是勾选框，不是状态灯**：带 ✓ 的平台参与本次搜索，没勾的本次不参与。一勾都不勾时点搜索会提示先选平台（统一提示，不区分"首次"还是"已勾过又取消"）。结果页每个平台有独立状态块，失败的可以单独重试。
- 「这次跳过」保留到当前标签页会话结束，刷新也不会反复提示；「以后不再自动提示」在关闭时写入当前浏览器。完成教程也停止自动提示。
- 帮助页总能重开，即使此前完成或永久关闭；重开不会清除原有永久偏好。进行中的步骤可在刷新后恢复。
- 收藏那一步的「回搜索结果」按钮跳回**搜索步骤本身**（卡片标题也随之切回），不是只改地址把卡片留在收藏页。
- **高亮框是"指认"，不是"拦截"**：`GUIDE_STEPS` 的 `highlight` 字段声明这一步要高亮哪个元素
  （写成 `[data-tour="..."]`，锚点在目标组件上）。浮层整层 `pointer-events: none`，
  压暗靠目标的超大 `box-shadow` 铺满视口 —— 没有额外遮罩元素，也不锁交互，高亮的东西照样能点。
  位置按视口坐标实算，`scroll` / `resize` / 元素尺寸变化都重算，所以滚动时框跟着目标走。
  取选项的过程见 `docs/decisions/2026-09-23-教程高亮框选.md`。
- **高亮的触发条件是"教程正停在这一步"，不是"用户还没做这件事"**：否则用户就是不勾平台、
  跑去别的页面逛，框会一直跟着他，变成 nag。同理，高亮不参与"该不该勾平台"的判断。
- **右下角有常驻的「退出教程」**：教程不锁交互，用户可能滚到任何地方，卡片会被顶出视口，
  所以需要一个不随页面滚走的出口（`.guide-exit` 是 fixed，和返回顶部按钮上下错开）。
  它的语义等同卡片里的「这次跳过」：只影响当前标签页，不写永久偏好。
- 许可接受前不展示；不与首次使用须知争抢注意力。文案同时提供中文和英文。
- 取舍见 `docs/decisions/2026-09-15-新手引导与诊断反馈.md`、`docs/decisions/2026-09-23-教程扩为逐页导览.md`、`docs/decisions/2026-09-23-教程高亮框选.md`。

## 已知坑 / 边界

- 偏好按浏览器和访问地址保存。更换浏览器、端口或清理浏览器数据后会重新出现；首次升级到带引导的版本时，老用户也会看到邀请。
- 关闭浏览器后若浏览器恢复了原标签页会话，临时跳过也可能被保留。帮助页始终可手动重开。
- 会话里记录的步骤号若超出当前步骤数（例如从新版本退回旧版本），按「新会话」处理并回到邀请卡。
- `onboarding.<key>*` 是动态拼接的键，静态扫 `t("ns.key")` 的那条 i18n 守卫看不到它们；加了步骤却忘写文案，由 `tests/test_webui_ui_contract.py` 里的 `test_onboarding_steps_have_copy_in_every_locale` 兜住。
- 完成教程只表示用户读完步骤，不作为真实登录、成功搜索或收藏完成的证据。
- 浏览器禁止写入偏好时仍可关闭本次引导，并提示无法记住长期选择。
- 七步时步骤条一定会换行（窄屏 2–3 行），`.guide-steps` 用 flex-wrap 处理，不需要额外布局。
- 本轮没有实测真实平台扫码；导航到账号页后的验证沿用该页已有行为。
- 目前只有「认识首页」这一步有高亮（指向搜索范围）。再加一处只需在 `GUIDE_STEPS` 里补 `highlight`、
  在目标组件上补 `data-tour` 锚点，并给两种语言各写一条 `onboarding.<key>Hint`；别的都不用动。
- 高亮框比目标外扩 6px（`GuideSpotlight` 的 `SPOTLIGHT_PADDING`），所以断言里偏移是 `[-6, -6, 12, 12]`。
  改这个常量要同步 `scripts/getting_started_smoke.py`。
- 提示气泡的文案**对读屏隐藏**（和卡片正文重复，不重复播报），因此两个浮层必须渲染在卡片外面 ——
  放进卡片那块 `aria-label` region 会污染无障碍树，也会让按 region 定位的测试匹配到两份文案。
- 指令卡片在教程进行中抬到遮罩之上（`.has-onboarding .getting-started`）。压暗它会让里面的按钮
  看起来像禁用态 —— 这一步是截图复核发现的，别顺手改回去。
- 窄屏下「收藏夹归属」会员弹层是 fixed 铺在底部的，退出入口的层级比它高，会浮在它上面。
  刻意的取舍：退出入口不该被任何东西挡住。
- 压暗色 `--siye-scrim` 深浅各一个值。深色主题背景本来就黑，照搬浅色那套透明度几乎看不出压暗。

## 测试怎么跑

- `webui/tests/onboarding.test.ts`：跳过范围、永久偏好、重开、刷新、步骤数边界与存储容错；高亮只指向 `data-tour` 锚点。
- `tests/test_webui_ui_contract.py`：每一步的标题 / 正文 / 按钮文案在两种语言里都存在；带高亮的步骤还要有 `<key>Hint` 文案，且锚点 `data-tour="..."` 在组件里真实存在。帮助页速查与教程互相指得到。
- 前端编译、测试、lint 按根目录 `AGENTS.md`。
- 构建后运行 `scripts/getting_started_smoke.py`，用隔离浏览器和模拟接口验证许可前隐藏、七步全程（含每步落地页与 URL）、平台零勾选、勾选跨刷新被记住、取消到零仍是零、回搜索结果、跳过、重开、刷新恢复以及窄屏布局。高亮部分另外验：框与目标偏移精确、滚动后仍精确、换主题与换视口后仍精确、**透过压暗层点得到勾选框**（证明没锁交互）、滚 600px 后退出入口仍在原位且可点；同时输出浅色 / 深色 / 窄屏三张复核截图到 `build/getting-started-review/`。
