# 界面渲染异常兜底

## 一句话

任一页面在渲染时出现未捕获异常，显示说明和「重新加载」入口，而不是整页空白。

## 代码入口

| 职责 | 位置 |
|---|---|
| 渲染异常边界与兜底界面 | `webui/src/components/layout/AppErrorBoundary.tsx` 的 `AppErrorBoundary` |
| 挂载位置 | `webui/src/main.tsx` |

## 关键决定

- **只兜渲染和生命周期异常**。事件处理器里的错误继续由各自的按钮文案和 toast 处理，不会被这层吞掉。
- **不自动重试**。同一份坏数据可能让重试立刻再次失败，反复循环比明确提示更难排查；用户可手动重新加载。
- **兜底不是修复**。它只保证界面不会白屏，具体触发原因仍要回到对应功能修数据或校验。

## 已知坑 / 边界

- 重新加载会恢复后端当前的搜索任务；如果同一份结果仍能触发同一个异常，会再次进入兜底。先修触发条件，不能只依赖这层。
- 错误只写入浏览器 console，不写库、不上传。
- 页面级兜底会把整个应用替换成说明页；搜索框等操作在重新加载前不可用。

## 测试怎么跑

前端在 `webui/` 运行 `npm run build`；构建后用浏览器打开页面，确认正常渲染。界面异常路径可用 Playwright 注入一个渲染期错误后检查兜底文案与「重新加载」按钮，不需要真实平台账号。
