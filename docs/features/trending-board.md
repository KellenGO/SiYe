# 热搜卡片（各平台热搜词）

## 一句话

首页的「最近搜索」旁边的卡片换成**各平台热搜**：顶部按平台切换，一次展示一个平台的热词，点一条直接用当前勾选的平台发起聚合搜索 —— 用来回答"同一条热搜，四个平台分别是什么反应"。

## 代码入口

| 职责 | 位置 |
|---|---|
| 卡片组件（平台标签 + 词列表） | `webui/src/components/trending/TrendingBoard.tsx` |
| 前端 hook（拉取 + 手动刷新） | `webui/src/hooks/useTrending.ts` |
| 前端 API 与纯函数（规整 / 标签页 / 取前 N / 热度格式化） | `webui/src/lib/trendingApi.ts` |
| 后端路由 | `api/routers/trending.py` |
| 后端取数与缓存（含小红书匿名聚合榜单、知乎首页问题热榜） | `api/services/trending.py` 的 `_fetch_xhs`、`_fetch_zhihu`、`_load`、`get_trending` |
| 响应模型 | `api/schemas/trending.py` |
| 首页挂载点与点击行为 | `webui/src/components/search/SearchPage.tsx` 的 `handleTrendingPick` |

## 关键决定

- **只取"词"，不取内容**。榜单产物只有「平台 + 词 + 热度」，内容交给已有的聚合搜索。
  这样不必为四个平台各写一套榜单详情解析，也不碰登录态与浏览器。取舍见
  `docs/decisions/2026-09-19-热搜卡片取代最近搜到.md`。
- **数据层按平台返回，展示层用标签切换**。聚合不可逆：丢掉平台归属就答不出"这个词是谁在热"。
  四个平台并排在那个位置挤不下（每列只放得下一行短词），切换才留得住"每个平台看多少条"。
- **小红书采用匿名第三方榜单**：经用户明确选择，使用 [UApiPro 公开热榜](https://uapis.cn/docs/api-reference/get-misc-hotboard)，
  页面标注「来源：UApiPro（第三方）」并链接到来源说明。只向固定地址请求小红书榜单，
  不读取本机登录态，不传 Cookie、搜索词、收藏或其他本机资料；不回退到需登录的官方接口。
  取舍见 `docs/decisions/2026-10-18-小红书热搜匿名第三方来源.md`。
- **获取时机只有两个**（用户明确要求）：**刚进软件时一次**（四个平台一起取回来）、
  **用户手动刷新**。除此之外不再自动获取——切页面、切平台、窗口聚焦都不触发。
  实现上分两层：前端把 react-query 的自动重取全关掉（`staleTime: Infinity`、
  `refetchOnMount/Focus/Reconnect: false`），后端缓存**不过期**，只有 `refresh=true` 才重新打上游。
- **进软件时四个平台并发取一次**，单平台失败只影响那一列（标签上仍能点进去看到原因）。
- **不用搜索冷却**：看榜不该把搜索拖进限流。热榜走的是独立链路，不占搜索的并发租约。
- **点击 = 直接搜**（有勾选平台时）：这是卡片的用法本身。一个平台都没勾选时只填入关键词，
  交给搜索框既有的"先勾选至少一个平台"提示，不绕过那条守卫。
- **取代了首页原来的「最近搜到」板块**：那块内容在搜索结果与历史里都能看到，
  而"各平台在热什么"是这里唯一能提供的新信息。首页偏好里的 `recent` 换成了 `trending`。

## 已知坑 / 边界

- 抖音、B站、知乎走各自公开入口，小红书经 UApiPro 聚合。四个平台均不需要本机登录态、签名或浏览器。
  小红书按照实际返回状态展示，加载中不提前标「暂不可用」；来源超时、空榜、异常结构或返回其他平台时只影响小红书，仍保留来源标注，其余平台可继续切换。
- 各平台热度口径不同，不跨平台比较或相加。小红书聚合源常用 `w`／万／亿表示热度，按单位转换后沿用现有展示；
  未知热度标签留空。知乎识别来源明确标出的「万／亿热度」，缺失或未知文案留空，不补占位数字。
- 知乎以用户指定的**首页问题热榜**为基准，取官方 App 域名匿名入口返回的问题标题与原始顺序，
  标题仍交给聚合搜索，不额外抓取问题内容。2026-10-18 复核发现旧 `top_search` 绕过本机缓存仍返回旧词；
  网页问题热榜需要登录，但 App 域名的同类入口可匿名取到 30 条问题。
  不回退搜索框关键词榜或旧入口；具体手机排名仍可能随更新时间、账号、地区或实验分组变化。
  取舍见 `docs/decisions/2026-10-18-知乎热搜以首页问题热榜为准.md`。
- 上游结构随时可能变，第三方服务也可能限流或延迟；本机刷新只重新请求来源，不保证来源刚刚完成更新。
  界面显示当前所选平台提供的更新时间，缺少时显示本机获取时间。取不到只给安全文案
  （"热搜暂时取不到，稍后再试"），**不回显上游响应原文**；也不写库、不上传。
- 缓存是**进程内**的：重启后端会重新取一次。这是刻意的，也可以当成"重新进入软件"。
- 小红书官方匿名入口在 2026-10-18 复核仍不可用；第三方榜单成功不代表官方匿名接口或登录态问题已解决。
  不用个性化推荐词冒充全站热榜，不携带第三方代码里公开的会话凭据。真实匿名 API 本次返回 20 条热词，来源与更新时间均通过本项目响应模型返回。

## 测试怎么跑

- 后端：`.venv/Scripts/python.exe -m pytest -q tests/test_trending.py --basetemp=.tmp_pytest_xxx`
  （模拟 HTTP／fetcher，不访问网络；覆盖四平台上游结构、小红书单位转换、匿名请求、来源穿过响应模型、知乎新入口与刷新替换、缓存与失败隔离）。
- 前端：`node node_modules/typescript/bin/tsc -p tsconfig.test.json` +
  `node run-compiled-tests.mjs`（`webui/tests/trending.test.ts` 覆盖规整、标签页与热度格式化）。
- 构建前端后运行 `.venv/Scripts/python.exe scripts/getting_started_smoke.py`：隔离浏览器和模拟 API，
  覆盖小红书词条与来源链接、桌面／窄屏、切标签不重取、点击搜索、手动刷新失败和旧版不可用响应兼容。
- 真机：起后端后打开首页，看四个标签是否都在、小红书是否标注第三方来源、点击是否搜索；来源可用性需持续观察。
