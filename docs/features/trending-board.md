# 热搜卡片（各平台热搜词）

## 一句话

首页的「最近搜索」旁边的卡片换成**各平台热搜**：顶部按平台切换，一次展示一个平台的热词，点一条直接用当前勾选的平台发起聚合搜索 —— 用来回答"同一条热搜，几个平台分别是什么反应"。只收抖音、B站、知乎；小红书没有全站热榜，卡片不为它留标签。

## 关键决定

- **只取"词"，不取内容**。榜单产物只有「平台 + 词 + 热度」，内容交给已有的聚合搜索。
  这样不必为每个平台各写一套榜单详情解析，也不碰登录态与浏览器。取舍见
  `docs/decisions/2026-09-19-热搜卡片取代最近搜到.md`。
- **数据层按平台返回，展示层用标签切换**。聚合不可逆：丢掉平台归属就答不出"这个词是谁在热"。
  多个平台并排在那个位置挤不下（每列只放得下一行短词），切换才留得住"每个平台看多少条"。
- 热搜词按卡片实际宽度排成一列或两列。较长的词条最多展示两行，热度单独对齐。
- **小红书不接入**（2026-11-05）：它的站内热点榜已下线（时间说法不一，见「已知坑 / 边界」），
  匿名官方接口不可用，原第三方聚合源又长期只刷新时间戳、不更新内容，所以整个移除 ——
  后端没有取数器、响应里不出现 `xhs`，前端也没有小红书标签与来源标注。
  取舍见 `docs/decisions/2026-11-05-小红书不接入热搜.md`。
- **获取时机只有两个**（用户明确要求）：**刚进软件时一次**（三个平台一起取回来）、
  **用户手动刷新**。除此之外不再自动获取——切页面、切平台、窗口聚焦都不触发。
  实现上分两层：前端把 react-query 的自动重取全关掉（`staleTime: Infinity`、
  `refetchOnMount/Focus/Reconnect: false`），后端缓存**不过期**，只有 `refresh=true` 才重新打上游。
- **进软件时三个平台并发取一次**，单平台失败只影响那一列（标签上仍能点进去看到原因）。
- **不用搜索冷却**：看榜不该把搜索拖进限流。热榜走的是独立链路，不占搜索的并发租约。
- **点击 = 直接搜**（有勾选平台时）：这是卡片的用法本身。一个平台都没勾选时只填入关键词，
  交给搜索框既有的"先勾选至少一个平台"提示，不绕过那条守卫。
- **取代了首页原来的「最近搜到」板块**：那块内容在搜索结果与历史里都能看到，
  而"各平台在热什么"是这里唯一能提供的新信息。首页偏好里的 `recent` 换成了 `trending`。

## 已知坑 / 边界

- 抖音、B站、知乎走各自公开入口，均不需要本机登录态、签名或浏览器。
- 各平台热度口径不同，不跨平台比较或相加。B站用 `heat_score`，抖音用 `hot_value`，
  未知热度留空。知乎识别来源明确标出的「万／亿热度」，缺失或未知文案留空，不补占位数字。
- 知乎以用户指定的**首页问题热榜**为基准，取官方 App 域名匿名入口返回的问题标题与原始顺序，
  标题仍交给聚合搜索，不额外抓取问题内容。2026-10-18 复核发现旧 `top_search` 绕过本机缓存仍返回旧词；
  网页问题热榜需要登录，但 App 域名的同类入口可匿名取到 30 条问题。
  不回退搜索框关键词榜或旧入口；具体手机排名仍可能随更新时间、账号、地区或实验分组变化。
  取舍见 `docs/decisions/2026-10-18-知乎热搜以首页问题热榜为准.md`。
- 上游结构随时可能变，公开入口也可能限流或延迟；本机刷新只重新请求来源，不保证来源刚刚完成更新。
  界面显示当前所选平台提供的更新时间，缺少时显示本机获取时间。取不到只给安全文案
  （"热搜暂时取不到，稍后再试"），**不回显上游响应原文**；也不写库、不上传。
- 缓存是**进程内**的：重启后端会重新取一次。这是刻意的，也可以当成"重新进入软件"。
- **小红书没有任何占位**：请求 `platforms=xhs` 时后端直接忽略该 slug，不打上游、不返回空对象，
  前端也会把旧响应里的 `xhs` 丢掉。将来若要恢复，需要先有官方、可匿名、口径明确的全站热榜，
  第三方聚合不算数；改的时候后端与前端都要一起改，只改一处会得到一个点不开的标签。
- 小红书没有全站热榜这件事本身有据：其搜索页的热点榜已经下线（具体时间报道不一致，
  2025-09 的约谈起于整改语境），现在只剩按搜索行为给出的个性化「搜索发现 / Discover」建议词，
  不能当作全站热榜。不要把个性化推荐词冒充成榜单。
- 「刷新」有 in-flight 守卫（2026-10-21）：一轮没回来之前连点不再叠请求；失败会进入 `error`，按钮回到可用态并显示"热搜暂时取不到"。此前 `loading` 只取 `query.isPending`，首屏之后恒为 false，`disabled` 等于没做。

## 测试怎么跑

- 后端：`.venv/Scripts/python.exe -m pytest -q tests/test_trending.py --basetemp=.tmp_pytest_xxx`
  （模拟 HTTP／fetcher，不访问网络；覆盖三个平台上游结构、知乎新入口与刷新替换、缓存与失败隔离，
  以及"小红书没有取数器、请求它也不打上游、不返回占位"）。
- 前端：`node node_modules/typescript/bin/tsc -p tsconfig.test.json` +
  `node run-compiled-tests.mjs`（`webui/tests/trending.test.ts` 覆盖规整、标签页、热度格式化，
  以及旧响应里的 `xhs` 会被丢掉）。
- 构建前端后运行 `.venv/Scripts/python.exe scripts/getting_started_smoke.py`：隔离浏览器和模拟 API，
  覆盖平台标签、桌面双列与 320px 单列、深色主题、切标签不重取、点击搜索和手动刷新失败，并断言热搜没有小红书标签。
- 真机：起后端后打开首页，看三个标签是否都在、点击是否搜索、刷新是否换词。
