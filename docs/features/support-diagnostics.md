# 诊断反馈

## 一句话

用户在帮助页主动复制一份可预览、可下载的本机状态报告，用于描述登录、搜索或收藏同步的问题。

## 代码入口

| 职责 | 位置 |
|---|---|
| 读取本机状态与报告字段白名单 | `webui/src/lib/supportDiagnostics.ts`（`collectSupportDiagnostics`、`buildSupportReport`） |
| 复制、预览、下载与反馈链接 | `webui/src/components/help/SupportDiagnostics.tsx` |
| 页面入口 | `webui/src/components/help/HelpPage.tsx` |
| 面向桌面用户的反馈模板 | `.github/ISSUE_TEMPLATE/bug_report.md` |

## 关键决定

- 主动点击才采集，复用本机健康、账号、当前搜索和收藏归档查询；单项失败不影响其余项，每项读取有超时。
- 从允许字段重新构造报告，状态与错误分类使用封闭枚举；不序列化原始响应、异常、日志、用户输入或任意字符串。保留版本、状态、数量、时间和耗时。
- 不收集 Cookie、昵称、关键词、结果正文、收藏内容、路径或完整日志；浏览器信息只保留类别，不记录完整 User-Agent。
- 报告复制到剪贴板后留在页面供预览。复制失败时提供手工复制与文件下载；用户自行打开反馈页、选择提交内容，应用不自动上传。
- 本地服务离线时依旧报告前端版本和浏览器类别，其他项明确记为不可用；没有历史记录与读取失败分别表达。
- 保留观察时间，不把历史成功当成当前可用性的保证；不将空结果解释成用户找到有用内容。
- 取舍见 `docs/decisions/2026-09-15-新手引导与诊断反馈.md`。

## 已知坑 / 边界

- 这是点击时的本机状态快照，不会为诊断额外登录或搜索平台。打开其他页面触发的既有自动验证不属于报告采集。
- 查询端点原本包含结果与昵称，前端构造导出内容时严格筛除；将来增加字段必须同步审查与白名单测试。
- 账号的未知错误代码显示为未知分类，不直接透传。某些信息为空时需要用户补充当时的操作与可公开的提示。
- 复制权限受浏览器控制；后端离线时，帮助页仍需已加载或有可用静态资源。

## 测试怎么跑

- `webui/tests/supportDiagnostics.test.ts`：敏感信息排除、类型容错、部分失败、离线、超时、只读请求范围。
- `scripts/getting_started_smoke.py`：实际浏览器内的复制、预览、下载及剪贴板拒绝路径。
- 文档结构与界面契约：`tests/test_docs_wiki.py`、`tests/test_webui_ui_contract.py`。
