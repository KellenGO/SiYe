## ① Installer 收尾

### 现状：链路其实已经通了

`scripts/build_exe.ps1` → `scripts/package_exe.py` → `scripts/build_installer.ps1`
→ `installer_clean_room_smoke.py`（静默安装 / 运行 / 卸载）→ CI 发 Release（安装器 + ZIP + 两个 sha256）。
落地页、使用说明、README、CHANGELOG 都已切到"安装器为主"。所以**不是重做，是补齐 4 个洞**。

### 缺口 1：版本号散在 5 处，而且界面上根本看不见

- `pyproject.toml:4`、`api/main.py:42` 与 `:129`、`api/services/environment_health.py:21`、
  `webui/package.json:4` —— 五处都写着 `0.2.2`。
- `/api/health` 其实已经返回 `version` / `version_match`，但前端只在**版本不匹配**时告警
  （`webui/src/lib/environmentHealth.ts`），用户正常使用时看不到版本号。
- 后果：发公测后收反馈，"你是哪个版本"要靠用户去翻 About 或直接问——报告质量会差一截。

改法：版本号单一来源（`pyproject.toml`），构建时注入前端；帮助页「项目与作者」区显示 `v0.2.3`
（页脚也行，但帮助页更顺手，因为诊断报告也在那儿）。

### 缺口 2：v0.2.2 之后有两个提交没发版

`4148bb9`（安装器发布路径）和 `257df13`（搜索词保留平台）都还没进 Release。
收尾就顺手发 v0.2.3：**先改版本号 → 提交 → 再打 tag**。
`scripts/build_exe.ps1:64-69` 会在 tag 构建时校验 `GITHUB_REF_NAME` 与 pyproject 版本一致，
不一致直接构建失败 —— 顺序反了会白跑一轮 CI。

### 缺口 3：卸载残留（记录为已知坑，可选做）

卸载器只删安装清单里的程序文件，登录 profile 和日志会留下（feature 文档已写明）。
想补的话可以在卸载时加一个"是否同时删除本机数据"的确认：**默认不勾**，且只清日志，
**绝不默认删收藏库**（`%LOCALAPPDATA%\SiYe\data\library.db`）—— 误删不可逆。
考虑到默认不删的收益很小，这条我建议**不做**，保持文档里那句说明就够了。

### 缺口 4：落地页那条 checklist 还没验证

`site/维护说明.md:179` 留了「首屏下载按钮真的能下到安装器（Release 已发布）」。
发完 v0.2.3 真机点一次直链 `releases/latest/download/SiYe-Setup-Windows-x64.exe` 即可。

### 不做

代码签名 / SmartScreen —— 没有商业证书，只能在说明里引导（已经写了）。

### 验收

后端 `pytest --basetemp=<新目录>`；前端 tsc + `run-compiled-tests.mjs`；
`scripts/build_installer.ps1` 出安装器；`scripts/installer_clean_room_smoke.py` 跑通。

## ② 搜索失败提示：黄卡 → 顶部蓝色弹窗 + 自动取消勾选

### 现状（要改的那张卡）

- `SearchPage.tsx:376-395`：只要本次搜索里出现 `login_required` 的平台，就在结果区上方
  常驻一张黄卡（`border-warn/30 bg-warn-soft/60`），带平台名圆片和「前往设置」按钮。
- 旁边还有一条 `overall === "partial"` 的黄条（`:310-317`），把 `error_summary` 平铺出来。
- 平台状态其实已经在 `PlatformStatus.tsx` 里有更轻的呈现（每个平台一个小状态块 + 重试）。

### 做法

**触发判定**沿用现有口径：只看 `displayJobResponse.platforms[p].status`，不解析 `error_summary`、
不用顶部账号状态推断（现有注释就是这么要求的，不要为了改样式去动判定口径）。

**弹窗**：用 sonner（`App.tsx` 已有一个 `Toaster`，`AccountsPage` / `Header` / `ResultTools`
等 5 处已在用 `toast()`）。

- 位置：页面上方居中。sonner 的 per-toast `position` 需要一个对应位置的 `Toaster` 才会渲染，
  所以要么在 `App.tsx` 再加一个 `position="top-center"` 的 Toaster 专给这类提示，
  要么把全局 Toaster 改成 top-center（代价：账号同步类 toast 也跟着从右上角挪到顶部中间）。
  **先验证 sonner 1.7 的 per-toast position 行为再定**，别猜。
- 配色：走品牌蓝 `--brand`（浅色 `#4ca4dc`，深色 `#78c8f3`）+ `--brand-soft` 底，
  **不用 warn / danger** —— 它不是错误，是"这次没搜到"的通知。
- 自动消失 5～6 秒；hover 暂停（避免用户正要点"去登录"时没了）。
- 文案三段：原因（陈述事实，不吓人）→ 已做的动作 → 出口。
  例：`小红书未登录，本次没有搜索` / `已自动取消小红书的勾选` / `去登录 →`（箭头图标）。

**自动取消勾选**：在 `SearchPage` 里对 job 终态加一个 effect，发现新出现的失败平台就
`handlePlatformsChange` 去掉它。注意别越过既有的"至少一个平台"不变量
（`SearchBar.tsx:109` 取消时 `next.size > 1`；reducer 里空集保持原偏好）。
如果取消会导致全空 → **保留勾选**，弹窗里说明"至少保留一个平台"。

### 三个要你拍板的点

| # | 问题 | 我的建议 |
|---|---|---|
| a | 哪些状态触发自动取消？ | **只对 `login_required` 自动取消**。`failed` / `timed_out` / `rate_limited` 多为暂时性（有冷却自愈，`PlatformStatus` 还提供重试），自动取消反而让用户下次进来少搜一个平台 |
| b | 取消要不要写进 localStorage？ | 现在勾选就是持久化偏好（`writePlatformPref`）。建议**照写**，弹窗里说清楚"已自动取消勾选"；否则用户下次进来它还是勾着、再失败一次。代价是用户登录成功后需要自己勾回来 |
| c | 黄卡删掉后要不要留痕？ | 建议删掉结果区那张黄卡，留 `PlatformStatus` 的状态块（已有）+ 弹窗里的"去登录"出口。若担心用户没看清，可在结果区保留一行很轻的灰字，不放黄色块 |

### 影响面

- i18n：新增 `search.*` 键必须**中英双语同时加**，`tests/test_webui_ui_contract.py`
  会卡"源码用到的键在每个 locale 都存在"和"两种语言键集合一致"。
- 脚本：`scripts/getting_started_smoke.py:145` 断言教程里出现「带 ✓ 的平台会参与搜索」，
  改文案要同步；`scripts/result_library_smoke.py` 也可能扫到结果区结构。
- 文档：`docs/features/search-experience.md`（提示呈现方式变了）。

## ③ 新手教程补上"平台勾选"

### 现状：你这个想法撞上一条硬约束

- 默认四平台全选：`readPlatformPref` 在没有存储值时返回 `[...PLATFORM_SLUGS]`
  （`lib/searchExperience.ts:157-165`）。
- 不允许取消到零：`SearchBar.tsx:109` 取消时要求 `next.size > 1`；
  reducer `platform_pref_set` 遇到空集直接保持原偏好（`:1248-1252`）。
- 所以"默认四个都不勾选"跟"至少一个平台"**直接冲突**，不是改个默认值就行。

### 三个选项

**A（推荐）：首次进入允许"零勾选"作为未选择态**
无存储偏好 → `[]`；此时点搜索不禁用按钮，而是提示"先勾选至少一个平台"——
这条提示本身就是最好的教学。用户一旦勾过任一平台，就恢复"至少一个"不变量。

- 改动：`readPlatformPref` 默认值、reducer 允许初始空集、`SearchBar` 的 `size > 1` 判断、
  `SearchPage` 提交前守卫。
- 测试要改：`webui/tests/searchExperience.test.ts:660`（初始 pref）、
  `:979-993`（"空集保持原偏好"这条断言要重新定义）、
  `scripts/getting_started_smoke.py:187`（断言关键词回填后 pref 仍是 `["douyin"]`）。
- 成本：中低。

**B：默认只勾一个**（小红书，或按已登录状态勾）
不改不变量，成本最低；"原来这是开关"的冲击感弱一些，但也能看出来。

**C：保持全选，教程里让用户亲手取消一个再勾回来**
零风险，不碰状态机；但依赖用户照做，不照做就还是学不到。

### 教程文案要补的（第二步）

- 平台按钮是**勾选框，不是状态灯**（你观察到的误会，正好写进去）。
- 没登录的平台可以先取消，不参与本次搜索。
- 结果页每个平台有独立状态块，失败可以单独重试。

### 影响面

- 两个 locale 的 `onboarding.searchBody` 等键（同样被 `test_webui_ui_contract.py` 卡）。
- `scripts/getting_started_smoke.py:145` 的文案断言。
- `docs/features/getting-started.md`。
