# 更新方向与难度评估（2026-09-18）

来源：昨晚自言自语定下的方向。本文只做**排期与难度判断**，不当作当前行为的依据
（当前行为看 `docs/features/*.md`）。

难度口径（★ = 半天以内、两个人以内文件改动；★★★ = 需要跨模块 + 真机验证）：

| 等级 | 意思 |
|---|---|
| ★☆☆ | 改文案 / 样式 / 单个组件，离线测试能覆盖 |
| ★★☆ | 跨 2–3 个模块，或有负面清单（隐私、兼容、迁移）要照顾 |
| ★★★☆ | 需要真机（真实平台登录态 + 网络）才能验证，改动本身未必大 |
| ★★★★ | 现有架构里没有对应入口，得先解决数据从哪来 |

## 一、这一波先做（不依赖 Codex 额度）

### 1. 新手教程细化 —— ★☆☆

用户反馈「再详细一点点，常用操作全覆盖」。现有实现：
`GettingStarted.tsx` 四步 + `lib/onboarding.ts` 的 `GUIDE_ROUTES` 四个跳转。

**已发现的具体问题**（不只是"不够详细"）：

- 「结果内关键词筛选在『导出 / 复制』中」这句是**错的**——筛选框是排序下拉旁边那个独立输入框
  （`ResultTabs.tsx` 的 `结果内关键词`），和导出面板无关。
- 没提结果卡右侧三个按钮的顺序与分工：**收藏 / 稍后再看 / 展开**。
- 没提「编辑归属」：一条内容可以同时属于多个收藏夹。
- 没提搜索设置里每平台数量（默认 20，上限 40）与"越大越慢、越容易触发平台限制"。
- 没提收藏页的**导出备份 / 导入**，也没提新版本会自动合并旧位置的收藏库。
- 「帮助与设置」一步没提托盘退出、theme/首页模式这些常用开关在哪。

改动面：`components/help/GettingStarted.tsx`、`lib/onboarding.ts`（步骤数与 session 正则
`^[0-3]$`）、两个 locale 的 `onboarding.*` 键、`hooks/useOnboarding.ts`、`HelpPage.tsx`（加常见操作速查）、
`scripts/getting_started_smoke.py` 的断言，以及 `docs/features/getting-started.md`。

**注意**：`tests/test_webui_ui_contract.py` 会卡两件事——源码里用到的 `t("ns.key")` 必须在每个
locale 都存在，且两种语言的键集合必须一致。加中文键忘了加英文会直接红。

### 2. UI 与提示优化（账号页提示、搜索页提示卡片）—— ★☆☆～★★☆

抱怨点是"和 UI 风格格格不入"。散在三处：`AccountsPage.tsx` 的扩展状态条与 `info-box`、
`SearchPage.tsx` 的提示卡、`index.css` 的 `info-box` / `guide-*` 样式。

改法建议：**只统一容器与语气，不新增颜色**。现在要是手写颜色值，第 6 项（自定义主题）
会从"加一层 token"升级成"改几百处硬编码"，纯亏。

### 3. Installer 收尾核对 —— ★☆☆～★★☆

主体已在（`installer/SiYe.iss`、`scripts/build_installer.ps1`、CI workflow、feature 文档齐了）。
剩下的多半是打磨项：版本号单一来源、图标与快捷方式、干净环境冒烟。
**先跑一遍 clean-room smoke 再判断剩什么**，别凭印象估。

### 4. 搜索质量的"离线可测"部分 —— ★★☆（不含验证）—— **已决定暂缓**

用户痛点：底部结果与关键词关系不大。代码里有两条**已知**成因：

- `lib/searchExperience.ts` 的 `AGGREGATE_WEIGHTS`：relevance 只占 0.4，
  freshness 0.2 + engagement 0.15 会把又新又热但不相关的内容往上抬。
- 多样性惩罚（`DIVERSITY_CONSECUTIVE_PENALTY` / `DIVERSITY_OVERREPRESENTATION_PENALTY`）：
  某个平台已经出了很多条时会被扣分，**等价于把其他平台的弱相关内容顶上来**——
  这正好解释"越往下越不相关"。

这两处改动本身很小，难点在验证：调权重没有真机搜索就等于没做。
所以拆成两半：**离线能做**的是给结果加"命中依据"和一个「只显示命中关键词」开关
（让用户看得见为什么、并且能自己收紧），**需要真机**的是权重调多少——留给 Codex 回来后做。

## 二、Codex 额度回来之后

### 5. 搜索质量（真机调优）—— ★★★☆

瓶颈不是代码，是**验证成本**：每次调参要真登录四个平台各搜一轮，且平台返回的弱相关内容
本身就是噪声源。建议先定一个可执行的判据（例如"前 20 条里标题或摘要命中关键词的比例"），
否则会陷入主观争论。

### 6. 观看历史 —— ★★☆～★★★

需要先定边界：**"看过"和"收藏"是两套东西还是一条记录的两个标记**。
现在本地收藏已经能存"全部 / 默认收藏夹 / 稍后再看 / 自建"，如果只是"看过"，
最省的做法是复用同一张表加一个 `viewed_at` 字段，而不是新开一套存储 + 页面。
定边界之前不要动手。

### 7. 多种主题色 —— ★★☆ —— **升级为加急**（原「自定义皮肤」降级而来）

界面本来就简洁，没有"皮肤"这一说；真正要的是**主题色**：在现有湛蓝基础上再给几种
（含 ChatGPT 那种石墨黑），深浅仍由主题开关独立控制。做法见
[主题色与观看历史](2026-09-18-主题色与观看历史.md)。
主要成本不在 CSS，而在把散落的品牌色硬编码收回变量（`index.css` 60 处 +
`Header` 11 + `AccountsPage` 5 + `LicenseDisclaimer` 4）。

### 8. 动画效果 —— ★☆☆（单点）～★★☆（全局一致）

## 三、排在 v1 之后

### 9. 热搜榜 —— ★★★★

现有 `aggregate_search/` 是**按关键词**起 worker 的，没有"平台热榜"入口，
且热榜多半要求"没登录也能看"。这是清单里不确定性最大的一项，建议只先做**单平台可行性验证**，
不要把四个平台一起排进去。

### 10. 发布公测版 v1 —— ★★☆

发布链路已通。剩下的成本在"收口"：版本号统一、落地页与说明同步、反馈渠道准备好。

## 四、已经决定不做（写了是负收益）

| 项 | 为什么不做 |
|---|---|
| 关键词过滤 | 会拖慢速度，且现状可接受（用户可以「换一批」）—— 2026-09-18 明确暂缓 |
| 接入淘宝等比价 | 与本项目的登录态搜索无关，等于另起一个产品 |
| Agent 管理收藏夹 | 收藏是高频手动操作，自动化的收益低于误操作风险 |
| Agent 拉字幕总结 / 接入 Obsidian | 点原链接 + clipping 已够，插件维护成本 >> 收益 |
| 按话题分类结果 | 搜索本身已按平台分组 + 结果内筛选，再叠一层分类实际用不上 |
| 壁纸 / 自定义背景 | 收益不明确，暂缓 |

## 五、建议的顺序

1. **现在**：新手教程细化 → UI 提示统一 → Installer 收尾核对 → 搜索质量的离线部分（命中依据 + 收紧开关）
2. **Codex 回来**：搜索质量真机调优 → 观看历史（先定边界）→ 皮肤与动画一轮打磨
3. **再之后**：热搜榜单平台试点 → v1 公测收口

**一条硬约束**：不要在这一波里动 `lib/searchExperience.ts` 的拆分（1,339 行的大模块）。
它同时被"搜索质量"和"UI 提示"两条改动盯上，先拆会让两边都要解语义级冲突。
