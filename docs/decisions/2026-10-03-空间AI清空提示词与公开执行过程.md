# 决策：空间 AI 清空内置提示词与展示执行过程

- 日期：2026-10-03
- 状态：已实施
- 相关：`docs/features/space-research-ai.md`

## 背景

使用者希望自行设计提示词，明确要求清空现有内置内容；同时希望界面接近其提供的 Claudian 截图，能调宽、展开，并直接看到工具调用过程。原有多段研究提示词与强制结构化输出会把普通回答判为失败，折叠的完成标签也不能反映执行过程。

## 选项

- 缩短系统提示词、继续强制研究结构：没有满足清空要求，普通聊天仍受固定结果格式约束。
- 清空提示词并接受普通回答，保留工具权限和可选结构化提交；展示公开执行记录与模型文字。
- 移植完整 Obsidian 插件运行环境：需要新的工作区和插件依赖，超出当前兼容四野的界面改动。

## 决定

选择第二种。OpenAI 不发送 system 消息，旧 SDK 使用空系统提示词，不再指定结构化输出格式。传给模型的仍有用户问题、空间及会话上下文、工具接口说明；不加入新的默认角色或写作规则。连接测试的测试请求独立保留。工具范围、来源访问限制、网页地址验证和笔记验证继续由程序执行。

工具执行前后分别记录状态并更新同一步；详情只展示有限执行摘要。模型在工具调用前公开返回的文字单独显示为过程说明，隐藏推理内容及签名只用于接口续接。侧栏可拖动与键盘调宽，展开后会话栏与聊天并排，沿用现有主题及手机模态布局。

## 后果

- 普通文字回答不因缺少固定栏目而失败，可追加笔记；基本标题、列表与加粗通过受限富文本转换，HTML 作为普通文字。
- 可选结构化提交仍校验引用；普通回答没有来源标识，不能自动判断其自然语言引用是否真实，读取记录保持独立。
- 清空的是四野的应用提示词，不能控制模型服务或旧 SDK 自身的内部提示内容。
- 当前工具轮次之间的公开文字和工具状态会随轮询显示；没有伪造隐藏思维链，也没有增加新模型框架或 UI 库。
