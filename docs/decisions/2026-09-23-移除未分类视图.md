# 决策：本地收藏去掉「未分类」视图

- 日期：2026-09-23
- 状态：**已实施**（前端移除入口；后端数据能力保留）
- 相关：`docs/features/favorites-library.md`

## 背景

「未分类」是早期遗留的动态视图，口径 = 已收藏、但既不在默认收藏夹也不在任何自建收藏夹。
它同时出现在本地收藏的列表侧栏和图标网格两处。用户明确反馈不需要这个分类，并说明此前已经强调过一次。

## 关键事实（决定了选项空间）

- 它不是一个真实收藏夹：没有独立的表与归属时间，口径随「加入/移出收藏夹」实时变化
  （`item.saved && !item.inDefault && !item.collections.length`）。
- 「全部」的口径已经独立（`saved` 状态 + `saved_count`，见 2026-09-21 收藏状态与稍后再看分离），
  所以删掉「未分类」不会让任何内容失去入口——这些内容照旧出现在「全部」里。
- 后端同时提供 `stats.unclassified` 与 `GET /api/library/items?unclassified=true`，
  属于「收藏归属」这一数据能力，且被 `tests/test_library_store.py`、`tests/test_library_api.py` 覆盖。

## 选项

| | 做法 | 代价 |
|---|---|---|
| **A** | 只删界面入口（侧栏 + 图标网格 + 选中态文案），后端字段与接口保留 | 前端留一个不再使用的 `stats.unclassified` 响应字段 |
| B | 连后端字段与 `?unclassified=true` 一起删 | 要动 schema / 路由 / 两个后端测试；「已收藏但未归夹」这一信息在数据层彻底消失，将来想再暴露要重写 |

## 决定

选 A。用户要的是"界面上不要出现这个收藏夹"，不是删掉一种统计口径；B 的收益（少一个字段）远小于
它在数据层造成的不可逆，而且 API 过滤条件本身不是界面元素。

- 前端：`FavoritesPage.tsx` 去掉侧栏项、图标网格卡片、`LibrarySelection` 的 `unclassified` 分支、
  计数 memo 与对应摘要文案。
- 后端：不动。`webui/src/lib/libraryApi.ts` 的 stats 类型保留该字段（响应里确实还有它）。

## 后果

- 界面上不再有「未分类」；内容仍全部可在「全部」里看到。想找"没归夹的"目前只能靠搜索/逐夹查看。
- 将来若要恢复这个视图：前端加回一处侧栏项 + 一处网格卡片即可，后端能力一直在。
