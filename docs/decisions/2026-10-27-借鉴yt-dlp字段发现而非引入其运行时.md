# 决策：借鉴 yt-dlp 的字段发现，不引入其运行时

- 日期：2026-10-27
- 状态：已实施第一项（抖音原生字幕）；其余候选未做
- 相关：`docs/features/space-research-ai.md`；[yt-dlp](https://github.com/yt-dlp/yt-dlp)（Unlicense）

## 背景

用户提出可只取 yt-dlp 需要的部分来改进空间 AI 的视频、图文提取。它是维护中的多平台下载器，能拿到格式、字幕轨与播放列表。我们此前在[分区读取与可选本地转写](2026-10-04-空间AI分区读取与可选本地转写.md)中明确「暂不引入 yt-dlp」，理由是安全边界而不是技术难度。

## 选项

- 把 yt-dlp 作为依赖或调用 `yt-dlp.exe`：能立刻拿到更全的字幕与格式，但它能跑任意 extractor、读 cookie 文件、调 ffmpeg、连任意域名，会破坏「模型不能触达工具与凭据」这条线；官方 PyInstaller 构建是 GPLv3+，与本项目的分发方式冲突。
- 完全不用，自己重写平台适配：安全但重复劳动，平台改版时容易漏字段。
- 只把它的 extractor 当**字段发现的参考资料**，用现有安全下载器取地址：不新增运行时依赖，仍走公开 DNS 固定与无 Cookie 下载。

## 决定

采用第三项。第一批只移植抖音原生字幕：详情里的自动字幕不在通用的 `caption_list` 里，而在 `interaction_stickers[].auto_video_caption_info.auto_captions`、`video.cla_info.caption_infos`、`video.subtitleInfos` 三处（位置对照其 `extractor/tiktok.py` 的 Douyin 实现）。中文轨优先，最多八个候选；字幕 JSON 的 `utterances` 按毫秒换算成秒。取地址仍走既有 `public_get` 与 `request` 节流，不传 Cookie。

## 后果

- 抖音有原生字幕的视频不再一律落到本地转写或字幕缺口；无字幕字段时行为不变，仍报「原帖未提供可读取的平台字幕」。
- 字段名依赖平台私有响应，平台改版会静默失效；测试用固定样本覆盖三条字段路径，真实账号未在本次复验。
- 只借用了字段位置与毫秒换算这两个事实，没有复制代码，也没有引入 yt-dlp、其网络层、ffmpeg 或 GPL 二进制。
- 仍不支持的：图文正文与配图（yt-dlp 把 `imageList` 当缩略图，那部分由 OCR 负责）、评论（它没有评论模型）、播放列表批量导入（属于产品形态变化，需单独讨论）。
