# 决策：以首条卡片可见为搜索体验目标

- 日期：2026-10-01
- 状态：已实施，真实本机 API 与模拟平台的浏览器验收通过
- 相关：`docs/features/search-experience.md`

## 背景

用户明确优先关注点击后尽早看到内容，剩余结果可以继续加载。普通聚合已经支持部分结果，但定时查询仍有展示延迟；单平台重搜主动忽略进度；旧平台标签和结果内筛选可能遮住新关键词最先返回的内容。

## 选项

- 进一步加快定时查询：仍有等待窗口，增加无变化时的本机查询。
- 增加独立推送协议：需要维护第二套传输与恢复路径。
- 在已有查询接口上有界等待任务变化：继续返回完整快照，沿用任务身份、取消与页面恢复机制。

## 决定

采用第三项。任务变化唤醒所有等待者，客户端传入已看到的版本；已经发生的变化立即返回，避免订阅窗口丢更新。等待最多十五秒，到期后继续等待；结果、状态、详情补全及收尾均发通知。关闭页面取消的是查询，不取消后台搜索；旧后端继续使用原有轮询。

单平台重搜只渐进替换目标平台，并保留已经显示的部分新结果。新关键词清除旧标签和结果内筛选，同一关键词操作保持选择。

## 后果

- 不增加平台请求、不引入依赖或第二套结果协议；仍由现有完整快照负责恢复和去重。
- 可消除内容已在后端但页面仍未取到的等待，不能承诺新关键词零网络延迟。
- 验收阻塞后续结果，直接断言第一张卡片已显示且所有平台仍运行；测量从后端放行到浏览器可见，不把该数字当作完整搜索耗时。
