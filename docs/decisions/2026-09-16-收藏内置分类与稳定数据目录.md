# 决策：收藏内置分类与稳定数据目录

- 日期：2026-09-16
- 状态：**已实施**
- 相关：`docs/features/favorites-library.md`、`docs/features/remote-favorites-sync.md`

## 背景

原来的「未分类」只是“没有自建收藏夹归属”的动态视图，无法表达用户主动收藏与稍后阅读两个不同意图。更严重的是，`library.db` 跟随源码或 EXE 所在目录：源码、旧发行包和新发行包会各读一份库。用户测试时看到 B站和小红书历史消失，实际数据仍在旧 `dist/MediaCrawler/data/library.db`，不是登录失败删除了内容。

## 选项

| 选项 | 优点 | 代价 / 风险 |
|---|---|---|
| 继续按程序目录存库 | 无迁移工作 | 每次换目录或版本都可能看见“空库”，无法形成稳定本机档案 |
| 只把路径改到系统目录 | 后续稳定 | 旧目录数据仍需用户手动寻找和导入，容易误判丢失 |
| 稳定系统目录 + 自动无损合并旧库 | 一次恢复历史，之后所有版本共用 | 启动迁移和冲突合并逻辑更复杂，需要备份、指纹和故障提示 |

内置分类也比较过“继续用虚拟未分类”和“把稍后再看做普通自建收藏夹”。前者无法表达主动意图；后者可能被删除、重命名，也无法保证卡片上的独立快捷操作。

## 决定

采用“稳定系统目录 + 自动无损合并旧库”，并把「默认收藏夹」「稍后再看」实现为条目上的两个独立布尔归属。自建收藏夹继续使用既有多对多关联表；「全部」只代表内容是否仍存在本机，不是可编辑归属。

Windows 默认数据库为 `%LOCALAPPDATA%\SiYe\data\library.db`，`SIYE_DATA_DIR` 仅用于测试和显式开发隔离。首次发现未迁移的旧库时先备份目标，再按内容键合并；源文件指纹用于幂等判断，源库变化后可再次合并。旧文件永不自动删除。

## 后果 / 边界

- 更换源码目录、解压目录或发行版本不再切换收藏库。
- 未登录或同步失败只更新本次状态，不删除任何平台历史归档。
- 旧 schema 中没有自建归属的内容进入「默认收藏夹」；已有自建归属不额外加入默认收藏夹。
- 用户可把条目移出所有收藏夹但继续留在「全部」；只有明确“从本机彻底删除”才删除内容本体。
- 历史自建收藏夹可能与系统名称同名，数据原样保留，界面加「（自建）」区分；以后禁止新建或改成这些名称。
- 本轮不移动浏览器登录 profile、日志和普通缓存，也不调整 500 条本地收藏上限。
