# 复用知乎搜索自带正文

- 日期：2026-10-11
- 状态：已实现，单条真实回答验证通过；全文完整性未验收
- 相关：`docs/features/content-reading.md`、`docs/features/search-experience.md`

## 背景

同一回答在日常浏览器可读，在四野独立 profile 中的网页与原项目带签名 HTML 请求均返回 403。然而搜索成功且返回独立的摘要和正文；此前聚合适配只保留摘要，打开阅读又访问失败的详情接口。原项目提取器本来就分别读取搜索对象的正文与摘要。

## 选项

- 增加原项目的带签名 HTML 回退：同一会话实测仍为 403，增加请求但没有取得正文。
- 读取日常浏览器已加载页面：需要扩展正文传递能力和浏览器侧交互，目前扩展只同步登录态。
- 复用当前搜索已取得的正文：不追加平台请求，适用范围由搜索实际返回的内容决定。

## 决定

采用第三项。只投影正文、匹配的内容标识及固定权限／付费／截断标记，通过私有 worker 事件送到后端，经现有阅读解析器移除脚本并保留段落与可信图片。正文不加入公开搜索 DTO 或分页快照，不写磁盘，按搜索任务的账号代数隔离，单项和总项数有界。

不接受摘要替代正文；显式不可读、隐藏、空正文或超限正文不缓存。搜索接口不保证完整性，因此统一标注可能不完整；主动刷新和无可用缓存时继续原有读取路径。

## 后果

- 搜索成功且有正文的结果可以在短时内阅读，避免无意义地再次访问失败的详情接口。
- 不引入依赖、数据库迁移、浏览器权限或新的登录方式。
- 两分钟后、后端重启后及未重新搜索的旧收藏不能据此保证可读；平台是否返回全文仍需与原网页对照。
- 搜索 API 可以只返回摘要，后端必须继续保留既有失败提示和原文入口。
