# 决策：Windows 安装器作为默认发布方式

- 日期：2026-09-16
- 状态：**已实施**
- 相关：`docs/features/windows-installer.md`、`docs/features/tray-launcher.md`

## 背景

此前普通用户需要下载 ZIP、完整解压、找到 `四野.exe`，升级时还要自己选择新目录。即使应用已经有稳定收藏库，解压式发布仍让用户面对目录权限、文件未完整解压、只复制单个 EXE、多个版本并存等问题。安装器应成为主路径，同时不能牺牲便携运行和本地数据安全。

## 选项

| 方案 | 优点 | 代价 |
|---|---|---|
| 继续只发 ZIP | 构建最简单、完全便携 | 首次使用与升级步骤多，容易留下多个版本或不完整目录 |
| MSI / WiX | 企业部署标准、策略支持较好 | 工程复杂，当前项目没有企业批量部署需求 |
| MSIX | 安装隔离和更新模型现代 | 需要签名，对可写运行目录、托盘和子进程约束更多 |
| **Inno Setup 的当前用户安装器 + 保留 ZIP** | 成熟、体积小、可无管理员安装，适合现有 onedir 应用 | 构建机多一个工具，未签名时仍会触发 SmartScreen |

## 决定

采用 Inno Setup，把 `SiYe-Setup-Windows-x64.exe` 作为普通用户默认下载；`SiYe-Windows-x64.zip` 降为便携备用。

- 默认目录是 `%LOCALAPPDATA%\Programs\SiYe`，使用固定 `AppId` 原地升级，不申请管理员权限。
- 安装开始菜单入口，桌面快捷方式由用户选择；保留标准卸载器。
- Release 同时发布安装器、便携 ZIP 和各自 SHA256；安装器在资产列表和页面 CTA 中排在前面。
- CI 必须执行「编译安装器 → 静默安装 → 完整运行烟测 → 静默卸载」，不能只检查文件存在。
- 不把用户数据写进安装包，也不在卸载时主动删除收藏库、账号 profile 或日志。

## 后果

- 普通用户不再需要理解“完整解压”和目录结构，升级也固定落到同一位置。
- 开发者和排障场景仍可使用 ZIP；源码运行方式不变。
- GitHub Windows runner 和本地发布机需要 Inno Setup 6.3+；CI 通过 Chocolatey 安装，构建脚本也支持显式指定编译器。
- 在取得代码签名证书前，安装器仍会显示未知发布者，文档必须明确官方下载地址与校验方法。

## 暂不实施

- 自动在线更新：需要独立的版本信任、失败回滚和签名设计，本轮只提供可覆盖升级的安装器。
- 卸载时询问是否清理账号与收藏：数据目前分布在稳定收藏目录和安装目录两处，贸然清理风险高；默认保留更安全。
- 强制桌面快捷方式和开机启动：都不应替用户做决定。
