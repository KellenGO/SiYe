# 决策：收藏后即时给出「编辑归属」入口

- 日期：2026-09-21
- 状态：**已实施**
- 相关：`docs/features/favorites-library.md`

## 背景

收藏按钮只做一件事：把内容写进默认收藏夹。想放进自建收藏夹，得先收藏、再切到收藏页、在列表里找到那条、点「编辑归属」。收藏夹一多，这个来回就成了主要摩擦点。

## 选项

| 选项 | 优点 | 代价 / 风险 |
|---|---|---|
| A. 收藏成功后在卡片下浮现一次「编辑归属」按钮 | 收藏仍是一步完成；不看归属的人不受打扰 | 想改归属要多点一次按钮 |
| B. 收藏即强制：点收藏直接展开归属面板 | 少一次点击，一步到位 | 每次收藏都要关面板，遮住结果列表；把"选文件夹"变成必填步骤 |
| C. 收藏弹一个文件夹选择框（单选，取代默认收藏夹） | 最贴近"归属=一个文件夹"的直觉 | 与既有的多对多归属模型冲突：批量导入、稍后再看、跨收藏夹统计都要跟着改 |

用户明确否掉了 B（"有点强制用户操作"），选择 A。C 的语义改动留到以后再单独评估。

## 决定

采用 A：收藏写入成功后，在该结果卡下方浮现一行「已加入默认收藏夹 · 编辑归属」，点开就是和收藏页完全同一套归属面板（全部 / 默认收藏夹 / 稍后再看 / 各自建夹）。

配套决定：

- **只在"加入"成功时触发**：移出收藏、写库失败、接口报错都不出现提示。
- **一次性**：关闭面板（完成 / Esc / 点外部）后整行收起，不再打扰；下次重新加入才会再出现。
- **聚合卡片按批次生效**：一条结果含多个平台版本时，点「全部加入收藏」后弹出的面板针对这一批来源同时修改，勾选框按"部分命中"显示半选。
- **默认收藏夹的语义不变**：面板里默认收藏夹仍是勾上的，要移出由用户自己取消。没有引入"选了别的夹就自动移出默认夹"的互斥规则。

## 后果 / 边界

- 归属面板因此从"只能在收藏页用"变成可复用组件，入参是收藏条目的 key 数组而不是单个 bookmark。
- 勾选状态需要三态（选中 / 半选 / 未选），新增纯函数 `collectionMembership` 计算，不放在组件里。
- 提示行不在 `.row-actions` 里：那里所有按钮被 CSS 固定成 34×34，文字按钮会被压扁。
- 后端无需改动：批量加入/移出收藏夹的接口本来就接受 key 数组。
