# 决策：重置同步只替换成功读取的平台本机归档

- 日期：2026-09-23
- 状态：已实施
- 相关：`docs/features/remote-favorites-sync.md`

## 背景

旧「重新同步全部」逐页写入本机，结束时只校正收藏夹归属；旧内容仍留在归档里。失败或取消也可能留下本轮已写入的页，不能直接改名为「重置同步」。用户要求日常同步只新增，而重置同步覆盖本机跨平台收藏，同时保全失败平台、未选平台和个人本地收藏。

## 选项

- 沿用旧 `full` 并改按钮名称：改动小，但不能兑现覆盖语义。
- 在真实归档中边读取边替换：失败或取消时需恢复旧数据，恢复点多且容易遗漏。
- 先在临时库完整读取一个平台，成功后以单笔本机事务替换该平台归档。

## 决定

采用第三项。前端在默认收起的高级操作里提供「重置同步」，用户确认后才发送 `reset` 请求。每个平台独立读取；完整成功才提交替换，失败、未登录或取消则丢弃临时库。普通 `auto` 同步及原有内部 `full` 兼容路径不变。替换仅触及所选平台的跨平台归档表，不触及个人本地收藏，也不向平台写入。

## 后果

重置过程中需要一份临时 SQLite 归档，占用额外本机磁盘空间；成功提交前页面仍显示旧数据。一个任务里已成功完成的平台不会因随后取消其他平台而撤销。平台没有一致性快照保证，因此「成功读取」指本次完整翻页及现有校验通过，不保证读取期间平台列表绝对静止。
