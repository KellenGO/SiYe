# 决策：平台勾选默认零勾选，首次进入不再全选

- 日期：2026-09-18
- 状态：已实施

## 背景

搜索框下方四个平台按钮（小红书 / 抖音 / B站 / 知乎）决定本次搜索范围。原实现首次进入默认四个全选，用户普遍把它误读成"这个平台能不能用"的**状态灯**，而非"要不要搜它"的**勾选框**——很多人根本不知道可以取消勾选。产品作者拍板：首次进入允许"零勾选"，引导用户亲手选择。

## 选项

- 保持默认全选，只在文案里解释（但状态灯的视觉误解无法靠文案消除）。
- 首次进入默认空集（零勾选），并把按钮明确讲成勾选框；零勾选时点搜索不禁用按钮，给出"先勾选至少一个平台"的提示。
- 完全移除"至少一个平台"约束，允许以空选择发起搜索（后端会 422 / 空跑，体验更差，且与既有偏好持久化逻辑冲突）。

## 决定

采用第二项，并统一提交时的提示规则：

- `readPlatformPref` 在**存储键完全不存在**时返回空集，实现"首次进入零勾选"；存储键存在但损坏 / 不可读仍回退全选，避免把用户卡住。
- UI 层（SearchBar）不再拦截"取消最后一个平台"，手动取消到零始终允许。
- 提交搜索时若零勾选：不禁用搜索按钮，仅在搜索框下方给出"先勾选至少一个平台"的提示（文案放在 `onboarding.*` 命名空间，与教程同源）。
- "至少一个平台"不变量只在**偏好已落地后**生效：偏好一旦写入 localStorage，reducer 的 `platform_pref_set` 传入空集会保留原偏好，不会把已有偏好清空。所以对"首次进入"与"已勾过又取消"采用同一条提交提示规则，不做两套。

## 后果

- 新手教程第二步重写：明确"按钮是勾选框不是状态灯"，并补上"没登录的平台可以先取消不参与本次搜索""结果页每平台独立状态块可单独重试"两条原本缺失的说明；顺手修正了"结果内关键词筛选在导出面板"的事实错误（实为排序下拉旁独立输入框）。
- 向后兼容：老用户已落地的偏好（非空集）不受影响；只有从未存过偏好的全新环境才会看到零勾选。
- 边界明确：零勾选只来自"存储键不存在"，损坏存储仍全选；偏好落地的空选择由 reducer 兜底保留，不会静默丢成空集。
- 新增 i18n 键 `onboarding.emptyPlatformPrompt`（中英文同步）；`getting_started_smoke.py` 与 `searchExperience.test.ts` 的断言已同步更新。
