# 决策：收藏指标只合并、不倒退；B站补全改用小并发

- 日期：2026-09-16
- 状态：**已实施**
- 相关：`docs/features/remote-favorites-sync.md`、`docs/features/favorites-library.md`、`docs/favorite-metrics.md`

## 背景

只读排查（未改代码）发现两件互相放大的事：

1. **保存动作会让已有的完整指标退化**。`remote_favorites_store` 用 `metrics = excluded.metrics`
   整列覆盖，`library_store` 更新时同样整列覆盖，job 内存结果也会覆盖 SQLite 里那份。
   于是「一次超时 / 被限流 / 只走到列表阶段」的同步，可以把以前完整的指标压成残缺版本
   —— 而库里的数据其实还在，只是这次没取到。
2. **B站 100 条在算术上补不完**。详情补全串行、每条间隔 2 秒、总预算 120 秒：
   100 条光等间隔就要约 198 秒，所以必然停在约 50 条。数据库里「51 条完整、49 条 failed」
   与这个上限吻合。

附带发现：详情缓存位于程序目录 `.cache/favorite_metrics`，源码版与发行版各一份，
换版本就要重新打一遍请求，再次撞上同一个上限。

## 选项

| 选项 | 优点 | 代价 / 风险 |
|---|---|---|
| 保持整列覆盖 | 实现最简 | 任何一次残缺同步都会永久丢掉已拿到的指标 |
| 按字段合并（新值优先、缺失沿用旧值） | 只升不降，语义贴近「这次没取到」 | 需要区分「缺字段」与「真的是 0」（0 一直是真值，不受影响） |
| 只在 status=complete 时整条写入 | 也简单 | 残缺同步会整条不更新，标题/封面等新鲜信息一起被丢掉 |

B站预算一侧：

| 选项 | 优点 | 代价 / 风险 |
|---|---|---|
| 只把总预算调大（串行） | 不改并发模型 | 100 条要 200+ 秒，会顶穿 worker 的 270 秒 |
| 小并发（2 槽位）+ 每槽位节流 | 100 条约 100 秒，留出余量 | 请求速率从 0.5 次/秒升到约 1.3 次/秒，风控敞口变大 |
| 放弃 100 条，把上限降到 50 | 零风险 | 与「每个平台最多 100 条」的产品口径冲突 |

## 决定

1. **指标只合并、不倒退**。新增 `api/services/favorite_snapshot.py` 的
   `merge_counts / merge_metrics_status / merge_approximate / merge_snapshot / merge_into_result`：
   本次拿到的字段覆盖旧值，本次没拿到的沿用旧值；完整度取两者较好者；沿用旧值的字段
   保留旧的近似标记。三个写入点全部改成走合并：跨平台同步落库、本地收藏重复保存、
   job 内存结果覆盖本机快照时。
2. **B站（含小红书、知乎）补全改成两个带节流的槽位**：每槽位间隔 1.5 秒，
   总预算 150 秒，槽位首次请求错开。缓存命中既不占间隔也不占预算。
3. **预算用尽不再抛超时异常**。以前会 `raise TimeoutError` 把整个平台判成「同步超时」；
   现在只是把剩下的行留给下次同步（那时是缓存命中），平台状态照常 succeeded。
   平台自己的错误（限流等）仍然立即终止整批，并取消其余在飞的槽位。
4. **缓存目录跟着收藏库走**：`library_data_root()/.cache/favorite_metrics`，
   源码版与发行版共用一份（与 `library.db` 同理，`SIYE_DATA_DIR` 可覆盖）。

抖音、小红书缺浏览量的补全路径**没有做**（列表接口本来就不返回，也不去试探未证实可用的接口）；
界面上也不额外加「完整 / 部分 / 失败」的角标——加了反而更糟心。

## 后果 / 边界

- 一次失败的同步不会让指标变差，最多是不更新；但**也不会自己变好**，仍然要等下次成功同步。
- 指标一旦取到就不会回退，所以真正的 0 必须由接口明确返回（现有代码已区分两者）。
- 请求速率约为原来的 2.7 倍。若 B站出现 412 风控，先降 `ENRICHMENT_CONCURRENCY` 到 1，
  再考虑调 `REQUEST_INTERVAL`。
- 冷启动（或缓存被清）时 100 条仍可能补不完：剩下的是 failed，第二次同步用缓存补齐。
- 详情页补全前的搜索结果被收藏时，保存的是当时的快照；之后再收藏同一条只会补字段、不清字段。
