# 决策：小红书不接入热搜榜

- 日期：2026-11-05
- 状态：**已实施**
- 相关：`docs/features/trending-board.md`；
  被替代：[小红书热搜使用匿名第三方榜单](2026-10-18-小红书热搜匿名第三方来源.md)

## 背景

热搜卡片最初只有抖音 / B站 / 知乎，小红书一直标成「暂未接入」。2026-10-18 曾按用户当时的明确选择，
接上 [UApiPro 公开热榜](https://uapis.cn/docs/api-reference/get-misc-hotboard) 作为小红书的匿名聚合来源，
界面标注「来源：UApiPro（第三方）」。

之后两点让这条线走不下去：

1. **来源停了。** 2026-10-24 复核时上游 `update_time` 卡住约 7 小时；00:07 时间戳跳变一次，
   但 20 条词与热度值一字未变 —— 第三方只刷新自己的时间戳，榜内容不再动。
   加随机参数、`Cache-Control: no-cache` 均无效（响应头本来就是 `no-store`）。
2. **平台本身没有这个东西可对。** 小红书的站内热点榜（原搜索页「小红书热点」）已经下线 ——
   关于下线时间说法不一：2025-09 平台因热搜生态被约谈并表态整改，媒体报道称热点榜是在
   "今年 3 月"（即 2026 年 3 月）从搜索页消失的，两者不能混为一谈。
   现在搜索页只剩按用户搜索行为给出的「搜索发现 / Discover」类建议词，属于个性化推荐，
   不是全站热榜。官方匿名热榜接口仍是 HTTP 406 + 空数据，匿名网页热词接口业务码缺登录信息。
   用户自己也确认：日常使用只见到 Discover，没有榜单。

也就是说，继续留着这个标签，等于把一份**来源看不见、内容不更新、口径也不是全站榜**的词，
摆成"小红书在热什么"。这比不做更糟。

## 选项

- 留着第三方标签，只在内容长期不变时加"来源可能已停更"提示：仍然是不可信数据，还要维护一套指纹比对。
- 换一个公开第三方来源：同样没有平台权威口径，且下一次停更依旧无人负责。
- 用本机登录态取官方榜单：与 2026-10-18 的"不使用登录态"约束相反，且官方页面本身已无该榜单。
- 把小红书从热搜卡片里整个移除（本次采用）。

## 决定

**小红书不参与热搜卡片。** 后端没有小红书取数器，`TRENDING_PLATFORMS` 只有抖音 / B站 / 知乎；
响应的平台列表里也不出现小红书，不返回空占位。前端标签同样只有三个，
第三方来源标注（`source_name` / `source_url`）随来源一起去掉。

保留的部分不变：只取词、点击即搜、进软件取一次 + 手动刷新、进程内缓存、
不进搜索冷却、失败只给安全文案。

## 后果

- 热搜卡片只剩三个平台；小红书"暂未接入 / 暂不可用"的标签、徽标和专属文案全部删除。
- 向 `/api/trending?platforms=xhs` 请求不会打上游，也不会返回 `xhs` 键 —— 有测试守住这一点。
- 若将来小红书重新上线全站热榜，需要一个**官方、可匿名、口径明确**的入口；
  第三方聚合不算数。届时重新评估并同步更新热搜 wiki。
