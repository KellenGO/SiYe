# 决策：新手教程从四步扩为七步逐页导览

- 日期：2026-09-23
- 状态：**已实施**
- 相关：`docs/features/getting-started.md`、`docs/使用说明.md`、`site/guide.html`

## 背景

教程一直只有四步（账号 / 搜索 / 收藏 / 帮助），首页、结果页的排序与筛选、结果卡片上的稍后再看与备注、
跨平台收藏、观看历史、外观与搜索数量设置都没有被介绍过。用户提出「完善新手教程，较为完整地介绍各个页面和功能」。

## 关键事实（决定了选项空间）

- 教程的既有形态是**内嵌卡片 + 跳真实页面**（`.getting-started` 占正常页面空间，不遮挡操作），
  不是遮罩高亮；步骤来源是 `GUIDE_ROUTES` 四条，步数校验写死 `/^[0-3]$/`。
- 卡片正文是普通流式文本块，宽度上限 `min(1120px, calc(100% - 48px))`。文案写长会把卡片撑高，
  把真实页面推到屏幕之外 —— 而"边看边操作"正是这个教程的形态前提。
- 应用只有七个路由：`#/`、`#/search`、`#/favorites/local`、`#/favorites/remote`、`#/history`、
  `#/settings/{search,accounts,appearance}`、`#/help`，正好可以一步一页。
- 帮助页已经是常驻页面，有「使用流程」「扫码登录」「从浏览器同步」「两种收藏」等静态小节，
  但没有逐页的功能速查；`docs/使用说明.md` 与 `site/guide.html` 是它面向站外的对应物。

## 选项

| | 做法 | 代价 |
|---|---|---|
| **A** | 七步「一步一页」+ 帮助页新增「页面与功能一览」：卡片只讲"这一页是什么、能做什么"，逐页细目常驻帮助页 | 一套内容分两处，两边都要跟着改 |
| B | 仍是四步，只把每步文案写长 | 卡片变成大段文字，首屏被挡住；"跳到某一步"失去意义 |
| C | 引入遮罩高亮（spotlight）逐页讲解 | 要动全站布局、z-index 与焦点管理；把"边看边操作"变成被动点击，风险与收益不成比例 |
| D | 完整介绍单独做成一页长文 | 与帮助页职责重复，且和七步教程互相抢入口 |

## 决定

选 A。

- 步骤收敛成单一来源 `GUIDE_STEPS`（`key` + `route`）：`key` 决定文案键，`route` 决定落地页；
  加删步骤只改这一处加两份 locale。步数校验改为按 `GUIDE_STEPS.length` 动态判断，避免下次再加一步又漏改。
- 卡片承担"带路"，帮助页「页面与功能一览」承担"查阅"，教程页脚负责把用户指过去；
  两边的互相指认写进 `tests/test_webui_ui_contract.py` 的守卫，避免只剩一边。
- 平台勾选框的说法必须与真实行为一致（默认一个都不勾、用户自己勾），所以同期修掉
  `parsePlatformPref` 的空数组语义，见 `docs/decisions/2026-09-23-平台偏好空数组语义.md`。

## 后果

- 步骤条从 4 项变 7 项，窄屏会换行成 2–3 行（`.guide-steps` 本来就是 flex-wrap，无需额外布局）。
- 逐页说明与 `docs/使用说明.md`、`site/guide.html` 里的"几步教程"必须同步，两处一起改。
- `onboarding.<key>Title/Body/Action` 是动态拼接的键，静态扫 `t("ns.key")` 的守卫看不到，
  因此加了 `test_onboarding_steps_have_copy_in_every_locale`：加步骤忘写文案会被它抓住。
- 以后首页 / 历史 / 外观这些页面改版时，要顺手更新帮助页那份速查（它现在是这些页面的对外说明）。
