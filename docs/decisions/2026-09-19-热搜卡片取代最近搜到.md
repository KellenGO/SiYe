# 决策：热搜卡片取代首页「最近搜到」

- 日期：2026-09-19
- 状态：已实施

## 背景

要做「热搜榜」：看各平台对同一条热搜的不同反应。落地前要在两个地方做取舍：
热搜榜放在哪，以及它是"榜单浏览器"还是"搜索入口"。

原方案考虑过放进搜索框的「推荐搜索」浮层（改动最省），但拿到抖音真实榜单后发现：
**热榜前几名大量是时政/新闻词**（实测当天为"中国女篮111:46大胜泰国""沙特首都利雅得遭空袭"等），
而浮层那个位置的语义是"帮我想搜什么"（现为剪辑、露营这类兴趣词）——语义错位。

## 选项

- 入口：搜索框浮层的推荐词 / 首页新增面板 / 导航新增入口。
- 形态：搬一份完整榜单（含内容） / 只取词当作搜索入口。
- 首页腾位置：保留「最近搜到」与其并存 / 用热搜替换「最近搜到」。

## 决定

- **只取词**：榜单产物只有「平台 + 词 + 热度」，点一条走既有的四平台聚合搜索。
- **放首页面板**，不占搜索框浮层；**替换掉原来的「最近搜到」板块**——
  那块内容在搜索结果页与观看历史里都能看到，而"各平台在热什么"是首页唯一能提供的新信息。
- **按平台分列**展示，不做混合榜单：这个卡片的价值就是平台之间的差异。
- **点击即搜**（用当前勾选的平台）；一个平台都没勾选时只填词，交给既有的"先勾选至少一个平台"提示。

## 后果

- 首页偏好里的 `recent` 换成 `trending`；旧版存的 `recent` 不被继承（读不到就用默认可见）。
- 首页右栏变宽（`1fr 1.9fr`，总宽 1080px），以便横向放下多个平台列。
- 目前只有抖音接入，卡片只显示有词的平台；其它平台接入后自动多一列，无需改前端结构。
- 后端缓存 5 分钟且**不进搜索冷却**：看榜不会让搜索被限流。
- 各平台榜单字段不一致（抖音是热度值），所以**没有做跨平台归一化**；
  将来若要做"多平台共识词"，应在前端由分平台数据合并，而不是在数据层聚合。
