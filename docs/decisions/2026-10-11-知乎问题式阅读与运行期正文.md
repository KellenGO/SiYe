# 知乎问题式阅读与运行期正文

- 日期：2026-10-11
- 状态：已实施；同一问题两条真实回答 API 与隔离界面验收通过
- 相关：`docs/features/content-reading.md`、`docs/features/search-experience.md`

## 背景

搜索正文短时可读、两分钟后又访问被拦详情，是本机缓存到期造成的。知乎问题标题和浏览量与回答的赞／评论混在一处，会把问题热度误认为单条回答热度，也忽视同问题其他回答。

## 选项

- 保持单条回答卡片，只修缓存：不能解决用户希望按问题浏览不同回答的需求。
- 把问题作为新的收藏内容：改变收藏身份、评论归属和空间资料处理；用户选择继续保存具体回答。
- 搜索按问题形成展示分组，详情按需发现更多回答，正文在本次运行保留：兼容旧回答记录，不增加数据库迁移或依赖。

## 决定

采用第三项。原始搜索与收藏身份不变，问题仅作为搜索展示分组；明确的问题总量与回答互动分别展示。问题卡片操作先选择回答，批量操作不默认选中整组，观看历史只记录实际阅读的回答。

取消知乎正文的时间失效和条数淘汰，不写磁盘，保留单项限制及内容清洗，按账号代数隔离并在账号变化时清理。去掉搜索正文统一“不完整”标记，保留明确权限、付费或截断提示；没有这些标记不代表对所有回答完整性作保证。

问题回答列表接口实测仍为 403，默认采用已验证可用的按标题搜索、赞数排序路径，严格匹配问题编号，按需分页且有加载上限。显示“已加载”，不将发现数量冒充问题回答总数，不把补充查询混入原关键词搜索。

## 后果

- 已取得回答不会因为阅读较晚或又搜索了四十条内容而失效；内存随本次取得量增长，关闭程序后需要重新获取。
- 搜索本身未提供正文的回答和未在本次获取的旧收藏仍可能被限制；不代表网页风控已解除。
- 已加载回答按赞数排序，不能宣称是全问题最佳或最高赞回答；标题搜索可能只发现部分回答。
- 原始搜索中的回答浏览量在同问题不同回答上重复；本轮隐藏该模糊口径，只有明确问题字段才用于问题指标。
