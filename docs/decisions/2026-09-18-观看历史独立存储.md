# 决策：观看历史使用独立 views 表，不复用收藏表

- 日期：2026-09-18
- 状态：已实施

## 背景

新增「观看历史」功能：用户点开看过的搜索结果自动记下来，方便回头再找。需求要求自动记录、只保留最近 1000 条、可删除单条与清空。

收藏库已有 `items` 表（`UNIQUE(platform, content_id)`），字段与历史几乎一致，表面上只需往里写即可。但收藏页的「全部」视图会列出库里每一条内容。

## 选项

- 复用收藏 `items` 表：写入时带一个标记区分「仅浏览」与「已收藏」。
- 在同库新建独立的 `views` 表，复用 `SqliteStoreBase`（字段照抄内容列，去掉 note / in_default / watch_later，加 first_viewed_at / last_viewed_at / view_count）。

## 决定

选择新建独立的 `views` 表。

原因：收藏页「全部」= 库里所有条目，若把历史写进收藏表，等于把用户「看过的」自动变成「收藏的」，历史会污染收藏，且会在收藏页、跨平台同步、备份导出等所有地方冒出来。独立存储让「看过」与「收藏」两套语义互不干扰，删除/清空历史也不影响收藏。

复用了既有的 `SqliteStoreBase` 底座（连接、事务、WAL、结果字段白名单），与 `remote_favorites_store` 的做法一致，没有自创存储层。

## 后果

- 历史与收藏各存各的，互不影响；历史页可独立删除、清空、滚动淘汰到 1000 条。
- 多一张表，但逻辑完全独立，没有跨表约束，维护成本可控。
- 记录必须静默：前端 `recordView` 是 fire-and-forget，失败被吞掉，绝不阻塞跳转；数据只在本机，不上传。
