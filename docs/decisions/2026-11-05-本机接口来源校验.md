# 决策：本机 API 的来源校验放在路由层，而不是靠 CORS

- 日期：2026-11-05
- 状态：**已实施**
- 相关：`docs/features/local-api-guard.md`

## 背景

2026-11-05 的代码审查里，一个只读检查用 FastAPI `TestClient` 调了
`DELETE /api/search/accounts/xhs/session`，**真的执行了 `shutil.rmtree`**，
把本机小红书的登录 profile 删掉了。这暴露的不是"测试不当"，而是接口本身
没有来源校验：任何能向 `127.0.0.1:8080` 发请求的东西都能删。

此前只有 `research_router` 与 `extensions_router` 挂了 `local_request`，
其余 57 个 `/api` 路由裸奔。

## 关键事实

- **CORS 挡不住这个**。CORS 是浏览器侧的**响应**读取策略。跨源 simple request
  （`Content-Type: text/plain`、`<form>` 提交）不触发预检，请求照发、副作用照发生。
  服务端看到的是一条完全正常的请求，只是浏览器不把响应交给攻击者页面。
- **DNS rebinding 连响应都能拿到**。攻击者把 `evil.example` 解析到 127.0.0.1，
  页面与 API 变成同源，读取也不受限。
- 实测：伪造 `Host: evil.example` 时，`GET /api/library/stats` 返回 200，
  而有守卫的 `/api/research/...` 返回 403。

## 选项

| | 做法 | 覆盖面 | 代价 |
|---|---|---|---|
| A | 只加 CORS 白名单 | 无 —— 本就不挡请求 | 零，但无效 |
| B | 每个路由自己抄一份校验 | 取决于是否漏抄 | 57 处复制，必漏 |
| C | 统一依赖，路由级 `dependencies=[Depends(local_request)]` | 全量、可断言 | 一次改造 + 测试客户端白名单 |

## 决定

选 **C**：

1. 实现收敛到 `api/routers/local_guard.py`，判断依据是 **Host 头**（必须是回环名）、
   **Origin 头**（缺失或本机来源）、**Sec-Fetch-Site**（不是 `cross-site`）。
2. 每个 router 用 `APIRouter(..., dependencies=[Depends(local_request)])` 挂载。
3. `/api/health` 显式豁免 —— 启动器和托盘要在后端就绪前探测它。
4. `tests/test_local_origin_guard.py` 遍历 `app.routes` 断言"没有漏挂的路由"，
   新增路由忘了挂会直接红。
5. 测试进程通过 `MC_API_ALLOWED_HOSTS=testserver` 放行 TestClient 的默认 Host。

## 后果

- 跨站页面与 rebinding 页面现在会在进入业务逻辑前收到 403，响应体是安全文案。
- **新增路由必须挂守卫**；守卫测试是结构性断言，漏挂即失败。
- `MC_ALLOW_NONLOCAL_API=1` 可以整体关闭（等价于允许 rebinding），
  仅用于调试；`MC_API_ALLOWED_HOSTS` 用于放行额外主机名。
- 局限：这套判断假定"本机 = 可信"。本机上其他用户进程仍可直接调用；
  若将来要支持局域网访问，必须叠加真正的鉴权，不能只靠 Host 白名单。
