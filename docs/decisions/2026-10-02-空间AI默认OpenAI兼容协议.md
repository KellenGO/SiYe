# 决策：空间 AI 默认使用 OpenAI 兼容协议

- 日期：2026-10-02
- 状态：已实施；聊天输出与执行记录已由[清空提示词与公开执行过程](2026-10-03-空间AI清空提示词与公开执行过程.md)调整，真实付费服务仍待使用者验收
- 相关：`docs/features/space-research-ai.md`

## 背景

使用者主要使用 DeepSeek 和 Gemini API，希望配置与更多服务兼容，并让研究助手像 Claudian 一样以聊天和会话为主。Claude Agent SDK 需要 Anthropic 协议；仅更换设置页的地址标签不能实现 OpenAI 工具调用兼容。

## 选项

- 在 SDK 前搭建协议转换代理：保留 SDK，但需转换工具结果、推理元数据和认证，增加一层本机服务及维护成本。
- 引入新的通用 agent 框架：功能较多，但增加依赖和打包成本，超出当前有限资料工具的需要。
- 复用现有 HTTP 客户端，实现有限的 OpenAI 工具循环，保留旧 Anthropic 路径：直接适配目标服务，并沿用现有资料、笔记与隔离进程。

## 决定

默认采用第三种方式。设置页提供服务商预设与可编辑的基础地址、模型和 Key；旧配置缺少协议字段时继续按 Anthropic 执行。默认接入不需要 Claude 账号或运行程序，不新增框架、库或数据库迁移。

OpenAI 模式只提供空间清单、分段资料读取、可选公开搜索与网页读取、结果提交。保留来源读取记录、引用校验、任务取消、内存历史限额与笔记追加保护。DeepSeek 的推理元数据及 Gemini 的工具签名在一次工具循环内原样回传，避免丢失服务要求的上下文；不会展示或写入诊断记录。

聊天界面按问题与回答顺序展开，读取操作默认折叠，资料缺口确认放在对应消息内；输入框固定在底部，会话列表支持搜索。每轮答案可单独追加到笔记，历史仍在当前运行期间保留。

## 后果

- 支持具备 OpenAI Chat Completions 工具调用能力的服务，不能保证仅支持文字生成、Responses 或 Gemini 原生接口的服务可用；连接测试要实测工具循环。
- 默认联网通过公开搜索页及受控网页工具实现，不依赖模型服务的厂商搜索功能；搜索页、网络和验证码可能导致缺口，默认关闭联网仍可使用空间资料。
- 不自动估算 OpenAI 兼容服务费用，只累计接口报告 token。真实模型权限、配额、费用和各平台资料需要实际使用者验收。
- 保留 SDK 的旧接入和打包能力，暂不清除相关依赖或运行程序；它们的维护仍需独立验证。

协议依据：[DeepSeek 官方文档](https://api-docs.deepseek.com/)、[Gemini OpenAI 兼容文档](https://ai.google.dev/gemini-api/docs/openai)。
