# 决策：资料获取复用账号会话与有界补取

- 日期：2026-10-05
- 状态：已实施；四平台小样本实测通过，冻结安装包兼容性待验收
- 相关：`docs/features/space-research-ai.md`、`docs/features/extension-login.md`

## 背景

Search 可以使用账号 profile，而 Research 的部分详情依赖进程内快照；重启会丢失快照，抖音还可能按默认全局平台打开错误目录。HTTP 签名接口与平台正常登录页面的访问结果也可能不同。笼统的读取失败无法解释真正的缺口。

## 选项

- 在 Research 中另存 Cookie、重建 crawler：产生第二套登录事实和生命周期。
- 持续刷新签名或反复重试接口：会重复触发平台限制，不能恢复权限。
- 复用 Accounts、平台 client、现有 HTML extractor 和有界浏览器会话：增加小型平台适配层，保持统一账号来源。

## 决定

采用第三项。账号服务提供明确平台的 profile 租用与必要快照恢复；Research 仍持有既有平台操作互斥。没有 profile 但有快照时使用临时上下文，不保存第二份凭据。恢复不是账号验证。

平台差异放在 ResearchBrowserProvider。只向固定平台路径执行正常登录上下文请求；小红书主评论受限时尝试一次浏览器补取，成功后分页沿用它；知乎复用正常页面和现有 extractor；抖音详情及B站字幕／播放资源有一次受控补取。缺少登录、验证码或拒绝访问时保留缺口，不做页面破解或人工行为模拟。初始化失败立刻关闭并释放 profile，防止后续资料等待同一把锁。

ASR 继续只接收临时媒体路径和固定配置。通用媒体下载不传 Cookie；当前实测资源可公开下载，不增加鉴权媒体通道。抖音选择详情已返回的低码率 MP4，跳过 DASH 独立流。组件状态由独立 worker 离线检查，不引入插件框架或向主 EXE 加入引擎／模型。

## 后果

- 正文、评论、字幕和部分成功结果独立保留；错误诊断只存固定分类、状态码及 fallback 结果，不能复制请求、响应或异常原文。
- 浏览器上下文需要进程及 profile 资源，仍受既有取消、时间和评论预算限制。
- 真人验收说明特定账号与样本成功；不能保证风控、登录有效期、CDN 或平台响应永远不变。
- 未来若媒体必须鉴权，需要单独的受控平台媒体获取边界；不得把 Cookie 交给通用下载器或 ASR worker。
- 产品化还需设置安装／删除组件、模型管理、组件版本升级与冻结安装包兼容性验收。
