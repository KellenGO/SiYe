# 决策：小红书本地图片文字识别

- 日期：2026-10-27
- 状态：已实现；源码、真实中文图片、界面和候选冻结程序验收通过；独立候选包已构建，未覆盖已安装版本
- 相关：`docs/features/image-ocr.md`；独立 SiYe-AI 扩展
- 插件提交：`a0f92b3`；主程序提交按 `AI-OCR-20261027` 定位

## 背景

小红书图文的核心信息经常在配图里，现有研究只有正文、评论和视频字幕，导致资料已经加入但核心文字没有进入模型。用户明确只需要 OCR。

## 选项

- 图片理解模型：可以解释画面，但超出文字识别范围，依赖服务商能力与费用。
- 新增第三方本地 OCR 引擎：跨平台能力更强，需要下载模型、增加依赖和分发体积。
- Windows 内置 OCR，复用现有 Pillow 解码：本机已有中文组件，无需新模型服务或依赖，符合当前 Windows 分发方式。

## 决定

采用第三项。采集端负责下载和识别，插件只接收文字。依据 [Microsoft OcrEngine 文档](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine)检测本机语言能力；中文组件缺失时提示补装，不擅自安装。

图片下载沿用公开 DNS 固定连接和逐跳检查，不发送登录 Cookie。格式解码与 Windows OCR 放在独立进程树，取消及超时一起终止；使用固定错误代号，不转发路径、链接或异常原文。长图保留重叠分块，避免缩图降低可读性。

系统 PowerShell 启动时按 [PyInstaller 的外部程序说明](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html#launching-external-programs-from-the-frozen-application)隔离私有 DLL 查找目录。图片通过受控 .NET 文件流交给解码器，避免 WinRT StorageFile 对冻结程序临时目录的访问限制；不能只用源码通过证明 EXE 可用。

文字按原图编号进入独立 OCR 分区，由既有必读检查、引用和会话背景机制处理。分图缓存避免重复下载识别，失败保留缺口。旧会话补取及回答后的重试另开问答轮次，不改旧答案或笔记。

## 后果

不增加依赖或图片模型费用，已有文字模型即可分析图片里的文字。识别后的文字仍会作为模型输入计费。Windows 中文 OCR 组件不是安装包自带，跨平台和复杂版面识别质量受限；明确显示缺失与失败，不能声称理解了画面。主程序承担 OCR，插件承担读取与展示，发布时必须同步更新。
