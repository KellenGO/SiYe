# 决策：搜索失败用顶部弹窗，并自动取消该平台勾选

- 日期：2026-09-18
- 状态：已实施

## 背景

某个平台没登录 / 被限流 / 超时而搜不到时，结果区会挂一张**常驻黄卡**，列出失败平台并给「前往设置」。
用户的反馈是：太丑，而且一直杵在那儿。同时另一件事没被解决——失败的平台仍然勾着，
下次搜索还会再失败一次。

账号页那边也在收敛口径：**用户只想知道"能不能用"，具体原因是给开发者看的**。

## 选项

- 保留常驻黄卡，只改配色和文案。
- 改成顶部弹窗（几秒后自动消失）+ 失败平台自动取消勾选。
- 什么都不提示，只在平台状态块里体现。

## 决定

改成**页面上方居中、品牌蓝、6 秒自动消失**的弹窗：第一行陈述原因（未登录 / 搜索失败 / 超时 / 被限流），
第二行说明"已自动取消 xxx 的勾选"，未登录时附一个「去登录 →」的出口跳账号设置页。

- **触发范围是"这次没搜到"，不细分**：`failed` / `login_required` / `timed_out` / `rate_limited` 都算。
  曾经考虑只对 `login_required` 自动取消（其余多为暂时性、有冷却自愈），用户明确要求失败就取消。
- **取消会写进持久化偏好**：下次进来不再白搜一遍。代价是用户登录成功后要自己勾回来。
- **结果区不留常驻卡片**：失败状态由 `PlatformStatus` 的状态块承担，弹窗只负责"这一次的通知"。
- 用品牌蓝（`--brand`）而不是 warn / danger：这不是错误，是"这次没搜到"。

## 后果

- 弹窗会消失，用户没看清就没有留痕；因此「去登录」只挂在未登录这类必须用户介入的情况上。
- 一次搜索里四个平台全失败时，勾选会变成空集——这正是"首次零勾选"（见
  `docs/decisions/2026-09-18-平台勾选默认零勾选.md`）允许的未选择态，提交时会提示先勾选。
- 同一 job 的同一平台只处理一次（用 ref 去重），effect 重跑不会重复弹窗。
- 失败原因只陈述状态对应的短句，不复述 `error_summary` 原文。
