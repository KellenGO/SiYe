# 决策：「已收藏」独立成状态，稍后再看彻底分开

- 日期：2026-09-21
- 状态：**已实施**
- 相关：`docs/features/favorites-library.md`、`docs/decisions/2026-09-21-收藏后即时编辑归属.md`

## 背景

原来的模型里，"是否收藏"和"是否在默认收藏夹里"是同一个字段（`in_default`）。这带来一个用户能直接撞到的怪现象：点收藏后再点一次取消收藏，内容仍然躺在「全部收藏」里——因为取消只是解绑了默认收藏夹，条目本体还在库里。

用户要的语义是清楚的：

- 「全部」= 所有**已收藏**内容的总览，不可编辑。收藏了就一定在，没收藏就一定不在，也不会在任何其他收藏夹里看到它。
- 「稍后再看」是独立的一条线，只由稍后再看按钮控制，和收藏体系互不干涉。
- 归属面板只管"收藏的归属"，不该出现"稍后再看"。

也就是说，**一条内容可以既不在默认收藏夹、也不在任何自建收藏夹，但它依然被收藏着**（于是仍在「全部」里）。这在旧模型里表达不出来。

## 选项

| 选项 | 优点 | 代价 / 风险 |
|---|---|---|
| 复用 `in_default` 兼作"已收藏" | 不用改库 | 表达不了"不在任何夹但仍收藏"，只能把取消收藏做成删除，误点丢备注 |
| 新增独立的 `saved` 状态 | 三个概念各归各位，规则都能说清楚 | 要改 schema、迁移旧数据、动前后端与导入导出 |
| 用"是否属于任一收藏夹"推导已收藏 | 不必加字段 | 与"可以一个夹都不放"直接冲突，未归类内容会凭空消失 |

## 决定

新增独立的 `saved`（是否已收藏）状态，与 `in_default`（是否在默认收藏夹）彻底分开：

- **点收藏** → `saved = 1` 且放进默认收藏夹 → 出现在「全部」。
- **取消收藏** → 整条记录从本机移除（与「从本机彻底删除」合并成同一个动作、同一个接口），备注与所有归属一并消失，因此必然从「全部」消失。
- **点/取消稍后再看** → 只动 `watch_later`，不碰收藏状态。取消稍后再看之后既没收藏也不稍后再看的条目直接删除。
- 归属面板只列「全部（不可编辑）」「默认收藏夹」和自建收藏夹，**不再出现稍后再看**。
- 归属面板里取消勾选「默认收藏夹」**不是**取消收藏，只是解除归属，内容仍在「全部」里。

### 同日调整：取消收藏与彻底删除合并

最初把"取消收藏"实现为"清归属 + `saved = 0`，稍后再看保留"，而"彻底删除"另外走删除接口。用户实际使用后指出这两者在界面上是同一件事（点了之后内容都不见了），要求合并，并且不再单独放删除按钮（原来在信息条最右侧加了垃圾桶）。

于是：取消收藏直接调用删除，信息条右侧的垃圾桶撤掉，「编辑归属」和「添加备注」回到原来的位置；改成在取消收藏时弹一次居中确认框（标题「是否要取消收藏」，副文案提示"只想换收藏夹请用编辑归属"），并带「下次不再提示」开关（localStorage）。

代价说清楚：一条内容如果同时挂在稍后再看，取消收藏会连它一起删——因为整条记录没了。用户知悉并接受（"他们从我的使用上看就是一个东西"）。

## 后果 / 边界

- 旧库升级时按"属于任一收藏夹"回填 `saved`；只挂在稍后再看上的旧条目判为未收藏（它们本来就不该出现在「全部」）。
- 备份格式升到 v4（多带一个 `saved`）；导入 v1–v3 时一律视为已收藏，与旧行为一致。
- `stats` 新增 `saved_count`（「全部」的口径）；`unclassified` 改为"已收藏但不在任何收藏夹"的数量。
- 「全部」视图不再等于"库里所有条目"，前端按 `saved` 过滤，不再直接拿全量 items。
- 取消收藏会连带丢掉这条内容的备注，也可能连带删掉它在稍后再看里的那份；用户可以在确认框里勾「下次不再提示」省掉每次确认。
- `POST /api/library/items/unsave` 只活了一小会儿就删掉了：它和 `DELETE /api/library/items` 表达的是同一件事。
