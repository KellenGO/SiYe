# 决策：教程加「跟着目标走」的框选高亮，但不锁交互

- 日期：2026-09-23
- 状态：**已实施**
- 相关：`docs/features/getting-started.md`、`docs/decisions/2026-09-23-教程扩为逐页导览.md`（本决策修订其中 C 选项的结论）

## 背景

用户提出：教程里需要强调的地方不够明显，希望在"让用户勾平台"的时候把全局变暗、给「搜索范围」加个高亮框；
并明确两点要求 —— **框选位置要精确**（鼠标滚动、控件上移时框要跟着动，"像缩在一个图层里"），
**不要锁交互**（只给提示），另外**右下角要有一个随时能退出教程的入口**，避免用户不按教程交互后卡住。

同日的 `2026-09-23-教程扩为逐页导览.md` 里，遮罩高亮（spotlight）是作为 **C 选项被否掉**的，
原话是"要动全站布局、z-index 与焦点管理；把边看边操作变成被动点击，风险与收益不成比例"。

## 关键事实（决定了这次为什么可以反过来）

- 当时把「铺一层遮罩」和「拦掉点击」当成同一件事否掉了。拆开看，两者成本差一个量级：
  **压暗可以是纯视觉的**（`pointer-events: none`），锁交互才需要焦点管理与点击拦截。
- 目标元素有稳定锚点可以直接用：平台勾选区是 `.scope.search-scope`（`SearchBar.tsx`），
  改成 `data-tour="search-scope"` 后，教程和页面之间就有了显式契约，也能被静态测试核对。
- 压暗不需要额外遮罩元素：给目标元素套一个超大 `box-shadow: 0 0 0 100vmax <scrim>`，
  阴影会铺满视口其余部分，中间天然留空。没有 z-index 战争，也不需要 `createPortal`
  （全站目前没有任何 portal）。
- `.getting-started` 的祖先链上没有 `transform` / `filter` / `backdrop-filter`
  （`glass-panel` 只用在 Toaster 上），所以浮层用 `position: fixed` 能正确定位到视口。
- 右下角**已经有主**：`.scroll-top`（返回顶部）在 `right: 24px; bottom: 24px`，
  且 `index.css` 里有一条注释说明窄屏下这个角落还要让给收藏夹弹层。退出入口必须和它上下错开。

## 选项

| | 做法 | 代价 |
|---|---|---|
| **A** | 精确框选（压暗目标以外 + 蓝色描边 + 贴着框的提示气泡），不拦点击，`scroll` / `resize` / 尺寸变化都重算位置 | 一个测量用的 hook + 两条 CSS；`--siye-scrim` 要分深浅两套 |
| B | A + 全屏遮罩并锁交互（真正的 spotlight tour） | 额外要 z-index 分层、焦点管理、点击拦截；把"边看边操作"变成被动点击 |
| C | 用箭头指向目标 | 静态箭头没有信息量；要指着走就得复用 A 的整套测量逻辑，表达力更低 |

## 决定

选 **A**。相对同日那份决策的 C 选项，这次是**缩小范围后的重开**，不是推翻：

- 只做「压暗 + 框选 + 贴着的提示」，**不做遮罩拦截**。高亮层整层 `pointer-events: none`，
  高亮区域和页面其它地方都照样能点 —— 教程的形态前提（边看边操作）保持不变。
- 高亮的触发条件是**教程正停在这一步**（由 `GUIDE_STEPS` 的 `highlight` 字段声明），
  不是"用户还没勾平台"。否则用户就是不勾、跑去别的页面逛，框会一直跟着他，变成 nag。
- 首次落地只做一处：`home` 那一步的「搜索范围」。理由：七步里只有它是"不知道该动哪里"的点；
  其余六步是整页导览，没有具体控件可指，帮助页那种整页长文也框不完。
- 右下角加常驻的「退出教程」，与 `.scroll-top` 上下错开；语义等同卡片里的「这次跳过」
  （只影响当前标签页，不写永久偏好）—— 卡片被滚出视口后，用户仍关得掉。
- 指令卡片抬到遮罩之上（`.has-onboarding .getting-started`）。它里面还有可点的按钮，
  压暗会让它们看起来像禁用态 —— 这是截图复核时发现的问题，不是设计上的偏好。

## 后果

- 新增 `--siye-scrim`，浅色与深色各一个值：深色主题背景本来就黑，照搬浅色的透明度会让压暗几乎不可见。
- 提示气泡与卡片正文重复，所以对读屏隐藏（`aria-hidden`）；说明仍由卡片那块 `aria-live` 承担。
  两个浮层因此**不能放进卡片的 `aria-label` region 里**，否则地标里多出的文案会污染无障碍树
  （首次实现放进去后，冒烟脚本里 `guide.get_by_text(...)` 立刻匹配到两个元素，被测试抓住）。
- `tests/test_webui_ui_contract.py` 原来用只认 `key` + `route` 的严格正则解析 `GUIDE_STEPS`，
  步骤对象一旦新增字段，那一步就会**静默漏出解析范围**（守卫还在、但已经不管它）。
  本轮把正则放宽，并新增两条守卫：带 `highlight` 的步骤必须有 `<key>Hint` 文案、
  锚点 `data-tour="..."` 必须在组件里真实存在。
- `scripts/getting_started_smoke.py` 新增常驻断言：框与目标偏移精确为 `[-6, -6, 12, 12]`、
  滚动后仍精确、换主题/换视口后仍精确、透过压暗层点得到勾选框（证明没锁交互）、
  滚 600px 后退出入口仍在原位且可点。截图三张（浅色 / 深色 / 窄屏）。
- 已知边界：会员弹层在窄屏是 `position: fixed` 且铺在底部，退出入口的 z-index 比它高，
  所以会浮在它上面。这是刻意的取舍 —— 退出入口不该被任何东西挡住。
