## 发布顺序

1. 在独立干净目录构建候选包，校验 ZIP／安装器及两份 SHA256；候选不能包含 `data/`、`browser_data/` 或 `.cache/`。
2. 完成上面的真人确认，记录无法验收或接受的边界。当前日常 `dist/` 是旧版本，不能直接上传。
3. 提交最终发布说明，将 CHANGELOG 的「待发布」改为实际日期，再打 `v1.2.0` tag；先核对 Git 状态与 tag 对应提交。
4. 推送与发布使用 `.github/workflows/release-package.yml`，检查四份 Release 资产与 SHA256。此文档的准备完成不等同于已经发布。
