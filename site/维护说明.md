# 四野落地页与使用说明 · 维护手册

> 这份文档是给**维护者**看的：怎么预览、部署、换图、改文案、发 Release。
> 想了解项目本身请看仓库根目录的 [`README.md`](../README.md)，想知道怎么用请看 [`docs/使用说明.md`](../docs/使用说明.md)。

`site/` 是给外部访问者看的落地页（介绍 + 下载）与使用说明，和 `webui/` 里那个本地 App 是两件事：

| | `webui/`（App） | `site/`（落地页 + 使用说明） |
| --- | --- | --- |
| 给谁看 | 已经装好并在本机运行的用户 | 还没下载、第一次听说项目的人 |
| 怎么跑 | 需要 FastAPI 后端 + `webui/dist` | 单个 HTML 文件，双击就能看 |
| 依赖 | React / Vite / Node.js | 无。可离线打开，也可直接丢到任何静态托管 |

`site/` 里有两个页面：

| 文件 | 作用 | 给谁看 |
| --- | --- | --- |
| `index.html` | 落地页：功能介绍 + 下载 + 许可 | 第一次听说项目的人，一屏看完决定要不要下 |
| `guide.html` | 使用说明：扫码登录、安装启动、搜索、排序筛选、收藏导出、扩展同步（可选）、常见问题 | 已经下载、想知道怎么用的人 |

两个页面共用同一套 CSS：改了 `index.html` 的 `<style>` 之后，把整段同步到 `guide.html` 里同样位置即可（用 `scripts/` 无自动同步，手改时一并改）。

同一份使用说明还有 Markdown 版：`docs/使用说明.md`（仓库内阅读，图片引用 `../site/*.png`）。改内容时两处一起改。

页面是**单文件**：CSS、JavaScript、图标、界面示意图全部内联，没有构建步骤，也没有必须联网才能加载的资源。

## 本地预览

直接双击 `site/index.html`，或者：

```shell
# 想要一个 http 地址（例如测试手机访问）
python -m http.server 8811 --directory site
```

## 上线

### 方式一：GitHub Pages（推荐，已配好）

仓库里已经有 `.github/workflows/pages.yml`：push 到 `master` 且改动了 `site/` 时会自动发布。

首次使用要做一次设置：

1. 打开仓库 **Settings → Pages**；
2. 把 **Source** 从 `Deploy from a branch` 改成 **`GitHub Actions`**；
3. 到 **Actions** 页面手动跑一次 `Deploy landing page to GitHub Pages`，或者往 `site/` 提交任意改动。

发布后的地址默认是 `https://kellengo.github.io/SiYe/`。

### 方式二：任何静态托管

`site/index.html` 一个文件就能用，也可以整个 `site/` 目录丢上去：Cloudflare Pages、Vercel、Netlify、对象存储、自己的服务器都行。没有构建命令，输出目录就是 `site`。

### 方式三：不进浏览器也能发

文件是自包含的，直接把这个 HTML 发给别人也能打开（对方本地双击即可）。注意这种用法下站外链接仍然需要联网。

### 改文案 / 改配色

- 所有文案都是页面里的中文纯文本，直接改，不涉及模板语法。
- **区块底色统一为白色**（2026-09-22 起）：两个页面的 `<section>` 都不再使用 `class="tint"` 的浅灰底，
  由卡片的 1px 边框 + 间距区分层级。`section.tint{background:var(--soft)}` 这条规则仍保留在样式里，
  想让某一段恢复灰底，给它加回 `class="tint"` 即可。
- **配色与字体对齐当前 App**，来源是 `webui/src/index.css` 和视觉稿 `style-preview/9-full-preview.html`：
  纯白底（深色 `#101219`）、发丝细线、单一靛蓝强调色 `#6573ff`（深色 `#8b95ff`），**没有毛玻璃、没有光斑渐变**。
  落地页把同一套 token 写在 `<style>` 顶部的 `:root` 里，改 `--brand` / `--brand-soft` 就能整体换色，深色在 `html.dark` 里。
- 字标「四野」下方那条渐变条是品牌标记，`--grad: linear-gradient(90deg,#6677fb,#29ddcc)`，和 App 的 `.home-wordmark::after`
  以及网站图标用的是同一组颜色；改色请三处一起改（`site/index.html`、`webui/src/index.css`、`webui/public/favicon.svg`）。
- 字体用 `"Segoe UI Variable Text","Segoe UI","Microsoft YaHei",system-ui`（与 App 一致），**页面不引用任何外部字体或图片**，
  整个 HTML 零外部请求，断网也能完整显示。深色模式默认跟随系统，右上角按钮可手动切换并记住选择。

## 先把 Release 建出来

落地页的下载按钮需要有东西可下：

1. 到仓库 **Actions → Windows Executable Release → Run workflow**（或推一个 `v*` 标签，例如 `v0.2.0`）；
2. 工作流会跑后端测试、前端测试、构建前端和 EXE，再编译安装器；便携目录与安装器分别经过 clean-room 验证；
3. 跑完后下载 artifact `SiYe-Windows-x64`，里面包含安装器、便携 ZIP 及各自的 `.sha256`；
4. 推送标签触发的工作流会自动创建并发布对应 Release，标题为「四野 v0.2.0」，并上传这四个文件；不需要再手动建立 Draft。

发布后 `releases/latest` 就会自动指向它，落地页不需要再改。

### 发布产物

普通用户下载 `SiYe-Setup-Windows-x64.exe`，安装后从开始菜单启动。安装器按当前用户安装，不要求管理员权限，支持覆盖升级与标准卸载。

需要免安装时再下载 `SiYe-Windows-x64.zip`。解压后是 `SiYe/` 目录，里面有两个运行入口：

| 文件 | 作用 | 用户要不要点 |
| --- | --- | --- |
| `四野.exe` | 托盘启动器（无窗口）：隐藏启动后端、自动打开网页、右下角托盘菜单 | **要**，推荐入口 |
| `SiYe.exe` | 后端服务 + 平台 worker（带控制台） | 不必；想直接看日志时可以双击 |

**为什么必须是两个 EXE**：平台 worker 是子进程，靠 stdin/stdout 管道与后端通信，所以后端那个
EXE 必须保留控制台（PyInstaller 的 windowed 模式会让 stdout/stderr 失效）。托盘启动器自身无窗口，
它把 `SiYe.exe --no-browser` 以隐藏窗口方式拉起来，输出重定向到
`data/logs/backend-<日期>.log`；托盘菜单里的「打开日志目录」就是打开那里。
两者共用同一份入口脚本 `tray_main.py`，靠命令行参数区分角色
（`--aggregate-worker` / `--no-browser` / 无参数=启动器）。

托盘行为：重复双击只打开已有页面（单实例文件锁 + 复用已在运行的后端）；右键「退出四野」会
连同后端进程树一起结束；后端 60 秒内没起来会弹一个可读的错误框并指向日志文件。

### 发 Release 的三个硬性条件（错一个下载就是 404）

落地页主 CTA 用的是稳定直链 `releases/latest/download/SiYe-Setup-Windows-x64.exe`，它要生效必须同时满足：

1. **asset 文件名必须一字不差**：`SiYe-Setup-Windows-x64.exe`（同时发布 `.sha256`、便携 ZIP 及其校验文件）。
   改名、加版本号后缀（如 `-v0.2.0`）都会让直链失效。
2. **不能勾 `Set as a pre-release`**：预发布不会被 `releases/latest` 指向，直链会 404。
3. **必须真的 Publish，不能停在 Draft**：草稿同样不参与 latest。

发布后在浏览器里直接访问一次直链确认能下载，再开始推广。

## 可粘贴的推广文案

都是根据 README 里的实际能力写的，没有超出项目现状的说法。用之前按平台习惯删改。

**一句话版**

> 四野：一次搜索，同时看小红书、抖音、B站、知乎。四个平台结果合成一个页面，统一排序、跨平台去重，能筛选、收藏、导出。Windows 一键安装，本机运行，数据不出电脑。

**三段版（论坛 / 群公告 / 公众号开头）**

> 找一个主题，以前要分别打开小红书、抖音、B站、知乎搜四遍，再自己来回对比，同一条内容还得靠眼睛认出来。
>
> 四野把这四个平台的搜索结果收进同一个结果页：并行搜索（单个平台失败不影响其他平台）、统一结果模型、综合 / 最新 / 互动最多三种排序、跨平台去重分组，之后还能按时间、类型、关键词筛选，收藏写备注，导出 CSV / Markdown 或批量复制链接。
>
> 全部在本机跑，后端只监听 127.0.0.1:8080，账号 profile 和收藏都不上传。开源，非商业许可。下载：[链接]

**技术向（V2EX / 少数派 / 掘金这类）**

> 开源了一个跨平台中文内容聚合搜索工具：把小红书、抖音、B站、知乎的搜索结果归一化成同一套 `UnifiedSearchResult`，再统一做排序、snippet 摘要、后台补全、编辑距离去重与分组。
>
> 后端 FastAPI + Playwright，四个平台跑在隔离的 worker 进程里，由 supervisor 管；搜索前有一次完全本地的登录预检（约 1ms，不启动浏览器就能判断哪些平台搜不了）；结果缓存 90 秒，明确限流后按 60/120/240/300 秒冷却，最近 100 次搜索的成功率、缓存命中率、P95 都有统计。
>
> 前端 React + Vite，Windows 安装器内置 Python runtime，并保留便携 ZIP。本机运行，数据不出电脑。非商业许可（fork 自 NanmiCoder/MediaCrawler）。

**发之前提醒自己**

- 页面和文案都要写明**非商业许可**（NON-COMMERCIAL LEARNING LICENSE 1.1），别写成「随便用」。
- 别说成「爬虫工具」或强调批量采集，这个仓库的产品主体是聚合搜索；README 也是这么定位的。
- 建议在推广帖里放一张真实结果页截图，转化差别很大。
- 平台风控和字段变化是已知情况，别承诺「稳定」「永远不会失效」。被问到结果不全时，可以直接引用页面的 FAQ 部分。
