四野

一次搜索，看遍四个平台

从不同的地方，找到你的答案。把小红书、抖音、B站、知乎的搜索结果收进同一个结果页： 并行搜索、统一排序、跨平台去重，接着筛选、收藏、导出。全部在你自己的电脑上跑。

  • 内置运行时，无需装 Python / Node.js
  • 只监听 127.0.0.1:8080

真实界面：四个平台的搜索结果合并在一页，统一排序、可筛选、可收藏、可导出（截图已隐去作者与互动数据）。

Why

四个平台 × 四次搜索，本来就是一件事

找一个答案的过程被平台切成了四份：每个站的检索、排序、互动口径都不一样，你只能靠记忆和来回切换把它们拼起来。四野只改一件事——把这一步合成一次。

现在（没有它）

四个平台 × 四次搜索

  • 依次打开小红书、抖音、B站、知乎
  • 同一个关键词，手动输入四遍
  • 四套排序规则，靠记忆横向对比
  • 同一条内容在多个平台重复出现，得自己认出来
  • 找到有用的结果，还得手动复制链接记下来

Features

搜索只是入口，能用起来的部分在后面

不是把四个网页塞进一个 iframe。后端把各平台结果归一化成同一套结构，再统一做排序、去重、补全和缓存。

四平台并行搜索

四个平台同时发起，支持部分结果返回。单个平台失败、超时或被取消时，其他平台的结果照常展示，并可对失败平台单独重试。

受控的 Provider fallback：轻量接口走不通时按已有路径回退。

统一结果模型

标题、摘要、作者、发布时间、封面与互动数据统一成同一种结构，跨平台也能按同一套字段阅读和对比。

互动数据按「播放 / 点赞 / 投币 / 评论 / 收藏 / 分享」固定顺序陈列，有值才显示。

三种排序

「综合」合并关键词相关性、新鲜度、互动表现与平台多样性；「最新」按时间；「互动最多」让评论、收藏等深度互动权重大于播放量。

结果内筛选与高亮

在「导出 / 复制」中按关键词筛选，也可切换平台查看；多个关键词用空格分隔，匹配标题、作者和摘要，命中词会高亮。

筛选只处理已经返回的内容，不会额外搜索平台。

跨平台去重与分组

同一条内容出现在多个平台时合并展示，同时保留每个平台的入口，可以逐个收藏或取消。

规则判断：标题相同或近似还需作者或有效摘要佐证，不靠同名硬合并。

本地收藏与备注

收藏保留当时的内容快照和原文链接，可写备注，刷新页面或重启程序后仍在。最多 500 个来源，每条备注 1000 字。

存在稳定的本机数据库（%LOCALAPPDATA%\SiYe\data\library.db），清浏览器缓存、升级或更换解压目录都不会丢；支持默认收藏夹、稍后再看和 JSON 备份（≤ 10 MB）。

跨平台收藏

只读拉取已登录账号在小红书、抖音、B站、知乎的收藏，在一个页面统一筛选、导出，或保存到本地收藏。

只发读取请求，不会在平台侧新增、删除或移动收藏。

导出与批量复制

未勾选时导出当前筛选下的全部结果，勾选后只导出选中的条目；CSV 带 UTF-8 BOM，Excel 打开中文不乱码，Markdown 适合整理笔记，也可以批量复制原文链接。

热搜卡片

首页按平台看各平台当前的热词（抖音 / B站 / 知乎），点一条就用当前勾选的平台搜它 —— 不知道搜什么的时候，从大家都在看的开始。

热搜只在进入软件时取一次，之后点「刷新」才更新。

搜索前登录预检

启动浏览器前先做一次完全本地的登录预检（实测约 1 毫秒）：确定搜不了的平台立刻提示「需要登录」并指向账号设置，不再白等十几秒。

cookie 库读不出来时一律放行，绝不因为读不出文件就把搜索拦掉。

单平台重搜 ⟳

每颗平台旁边一个 ⟳：只重跑这一个平台，拿到的是与上一轮不重复的新内容，替换它自己那一份，其它平台完全不动，也不会多出一批。

「换一批」才是往后叠加新内容，「刷新结果」是整组重搜 —— 三种刷新各管一件事。

没搜到会说清原因

某个平台 0 条 / 失败 / 限流 / 未登录时，页面上方直接说明原因（被平台风控时显示「疑似平台风控」），并自动取消它的勾选，不用再对着「无结果」猜。

更多底层能力：摘要补全与缓存、搜索统计与限流、账号诊断

摘要补全与缓存

先用 snippet 摘要，缺少有效摘要的前排结果由后台补全，不阻塞首屏。90 秒短期内存结果缓存，可强制重新搜索。

搜索统计与限流冷却

最近 100 次搜索的耗时、平台成功率、缓存命中率、备用路径使用率和失败原因一目了然，也可直接读接口做对比。

平台明确限流后进入 60 秒冷却，重复触发依次延长为 120 / 240 / 300 秒封顶；其他平台继续搜。

账号状态与平台诊断

账号设置里点「扫码登录」用手机扫一下即可完成登录；装了浏览器扩展的话，打开程序还会自动为未确认登录的平台同步一次。平台诊断会分别展示账号状态、当前搜索路径和 fallback 能力。

账号状态不等同于搜索能力，没登录也可能完成公开搜索。

Windows 可执行包已经包含 Python runtime、FastAPI 后端和生产版 Web UI。普通使用不需要安装 Python、uv、Node.js、npm。 先连接常用的 1–2 个平台：在「账号与登录」点「扫码登录」，用手机扫一下即可，不需要安装任何插件。应用内提供可跳过的新手引导。

下载安装器

下载并运行 SiYe-Setup-Windows-x64.exe，只从项目官方 Release 获取。

2

安装并启动

按向导安装后，从开始菜单启动「四野」；程序在托盘运行，浏览器会自动打开，不弹控制台。

3

扫码登录，然后开搜

在欢迎卡点「带我试一次」，或直接到「设置 · 账号与登录」扫码连接常用平台。搜索时只勾选已连接的平台，其他平台以后再添加。

下载 Windows x64 安装包

安装器由 GitHub Actions 在 Windows 上真实构建，并经过静默安装、运行和卸载验证后才上传；同时提供 .sha256 校验文件。便携 ZIP 仍在 Releases 中提供。装好之后怎么用，看使用说明。

前往 Releases 下载 查看源码

如果 Releases 里暂时还没有可下载的包：在仓库的 Actions 页面手动运行 Windows Executable Release 工作流即可生成安装包。 程序没有代码签名，首次运行若被 Windows SmartScreen 拦下，点「更多信息 → 仍要运行」即可（详见使用说明）。

  • 系统：Windows 10 / 11 x64
  • 浏览器：系统 Chrome 或 Edge（Windows 通常自带 Edge）
  • 浏览器插件（可选）：随包提供。已经在浏览器里登录过平台时，装上它可以一键同步登录状态、省掉扫码；不装也能用扫码登录
  • 端口：默认 127.0.0.1:8080，只监听本机
  • 隐私：账号 profile、缓存和运行数据都存在本机目录，不上传

运行期间不要删除 EXE 旁边的 _internal、webui 等运行文件。如果 /api/health 显示浏览器不可用，先装好或修复 Chrome / Edge 再重启。

先连接你常用的平台

四野用你本人的登录状态搜索。先连接常用的 1–2 个平台并勾选它们，其他平台可以以后再添加。

  1. ① 扫码登录（推荐）：打开四野的「设置 · 账号与登录」，在平台卡片上点「扫码登录」。 程序会在你电脑上打开一个浏览器窗口，用对应平台的手机 App 扫码，看到「登录已确认」后即可搜索该平台。重启后会自动复核已有登录状态。
  2. ② 可选：用浏览器扩展同步：如果你平时就在 Chrome / Edge 里登录着这些平台， 装上随包的插件（chrome://extensions → 开发者模式 → 加载已解压的扩展程序 → SiYe/browser_extension/）， 回到「账号与登录」点「从浏览器同步」即可省掉扫码。不装也能用扫码登录。

两种方式可以混用。插件只把必要的会话信息交给本机后端，用于在你自己的账号下搜索。请只同步和使用你有权使用的账号。详细步骤见使用说明。

装了扩展的话，程序打开时会自动检测账号状态，并为尚未确认登录的平台自动同步一次；平台诊断会分别展示账号状态、当前搜索路径与 fallback 能力。

扫码登录与搜索同一时间只处理一个（后端排他保护），稍等几秒即可；扩展同步进行中发起搜索，也会等同步结束后再提交，不会把你卡住。

FAQ

你大概会问的几个问题

用之前必须先登录四个平台吗？

不用全部登录。建议先在「账号与登录」扫码连接常用的 1–2 个平台，搜索时只勾选它们。部分公开搜索路径可能无需登录，但可用性受平台状态影响；需要个人收藏同步时必须确认对应平台的登录状态。

没登录时，搜索前的本地预检会在毫秒级告诉你是哪个平台搜不了、为什么，并把你引到账号设置，而不是让你白等浏览器启动。

我的账号和数据会被上传到服务器吗？

不会。后端只监听 127.0.0.1:8080，搜索请求由本机发出；账号 profile、缓存和运行数据都在本机目录里。

本地收藏和备注存在本机数据库（%LOCALAPPDATA%\SiYe\data\library.db）里，旧版本目录会在启动时无损合并；导出 / 导入 JSON 备份也完全在本机完成，不上传任何内容。

搜索结果里显示「缓存」是什么意思？

后端对搜索结果做 90 秒的短期内存缓存，同一关键词在 90 秒内重复查看会直接回放缓存，平台状态里会显示原采集时间。

点「重新搜索」可以强制拿到最新结果；重复查看和后台摘要补全不会延长缓存有效期。缓存成功才更新，失败时会保留尚未过期的旧缓存。

某个平台搜不出结果 / 结果不完整怎么办？

先看平台状态：需要登录就按提示去「账号与登录」扫码登录（或用扩展同步）；明确被限流会显示冷却倒计时，冷却期间重复搜索不会向该平台发新请求，也不会延长倒计时。

单个平台失败不会影响其他平台返回结果，可以对失败平台单独重试。冷却结束后的重试需要手动点。

为什么有些结果的互动数据不完整？

各平台搜索接口提供的字段本来就不一样：小红书和抖音的搜索接口不返回播放量，B站的投币数只在视频详情里，知乎搜索结果不返回收藏数。

缺失的指标不会占位，也不会为了凑数字额外逐条抓详情。这是已知限制，不是显示错误。

能在 Mac 或 Linux 上用吗？

目前只提供 Windows x64 可执行包，Mac / Linux 暂时没有现成安装包。后端和前端都是跨平台的，源码方式可以自行构建，具体步骤见 GitHub 仓库的 README。

想在手机上用的话，可以看同源的 Android 客户端 OpenScope（独立仓库，由朋友维护）。

启动时提示 8080 端口被占用？

先关掉已经在运行的本项目实例（或占用该端口的程序）。程序不会强制终止其他应用，也不会自动改端口。
